## 3. Starter behaviour and explicitly excluded work

**What an empty starter needs, at minimum:**
1. A new **starter-only Unity scene** (or exact source-confirmed equivalent), flat ground default 30×30 m with configurable footprint; no trees/paths/racks/fences/roads/structures/crops. Player spawn and ordinary walkable ground controls permitted.
2. The same **real code/UI foundation**: common menu/HUD/Stand Map/Work Plan/Annual Review/Objective label and tree inspection only where relevant. References to shared existing implementations, no script cloning or synthetic second tree inventory.
3. **Empty-safe presentation**: map displays actual empty site extents with no ghost trees/clearing; Work Plan says **no eligible operations** rather than populating fictitious tasks; Annual Review says **no year advanced / no review available**, no phantom year/cash/outcome; no rack tools/help/markers/lessons in a no-rack blank scene; controlled disabled states where ecology/manager cannot honestly work without initial roster. Do not forcibly advance an annual ecological clock to make the UI look active.
4. **Copy quality:** duplicate only the scenario-specific scene/config/authoring-content asset(s) (or instantiate and configure a clearly reusable supported prefab composition); set a second demonstrably different footprint, e.g. 45×60 m **TEST ONLY**, without copying code or modifying the original; no guarantee of a 45×60m production scenario or signed geometry.
5. **Text:** permanent titles `Work Plan`, `Stand Map`, `Annual Review`, `Objectives` display; scenario intro/objective/guidance etc. are empty/optional with obvious **developer-only preview** markers; production content validation prevents them being shown as player facts. Real dynamic values come from engine, not an editable text field.
6. **Save safety:** starter is **authoring-only, no persisted world identity** by default. Save/Load/Continue-from-file targeting old `forest-save.json` must be provably inaccessible/refused from starter, including F5/F9 AND menu buttons. Implement only the smallest safe gating after separately approved source scope and exact guard tests; **no new save file, profile, serializer or identity literal** in this task. No historical main modification is permitted without named 3D source owner and saver coordination.

**Explicitly excluded from the template-first task:** planting/growth/recruitment/deer/annual consequences in an *empty* starter, species authoring, 175 Sitka Compact roster, H1 path, guards/fence, scene beautification, new global scenario picker, multi-world Save/Continue policy, browser editor runtime adapter, additional Multi engine, 2D UI, multi-rack engine convergence, Unity 3D rebuild, any new packages, shaders/models, Windows Player build, owner-signed world digest. Those belong in existing/independent feature tasks and require their own approval.
