### A. Invariants to preserve
- **One established Unity/3D baseline** from original five-rack Scenario One. Reuse existing UI controls/systems: `StandaloneSessionMenu`, `ScenarioOneUiRoot`, `WorkPlanView`, `StandMapView`, `AnnualReviewView`, `TreeInspectionView`, `ScenarioOneManager`, `ForestEcologyController`, `ForestTree`, `ForestSaveController` as **observed source components**. - **New 3D scenarios are configurations/content** with real scene/terrain/roster/species/initial conditions/objectives/allowed operations, not separately rebuilt Work Plan, map, annual simulator or general menus. Original five-rack world remains intact.
- **Real forestry outcomes** only from authoritative trees/ecology/work/economy state. UI is presentation/commands; no additional simulated inventory or one-screen fake progression.
- **Multi 2D engine independent now**: source-owned one-area 30×30m 100-Sitka synthetic fixture, exact case-sensitive tree identity, one immutable atomic source-token/current frame with plan revision, pending→approve→atomic execute Fell→Year+1; do not transfer Unity `ScenarioOneManager`, `ForestEcologyController`, Unity scenes, UI Toolkit or saves into Multi. Multi G1 comparison DISABLED/Manual/NotCovered and economics UNAVAILABLE until genuinely implemented. Not a five-rack property.
- **Shared game semantics ≠ shared binaries**. Reuse map visual language and world-metre/north-up math wherever validated; source reuse is conditional on complete transitive compile-linked file scope and named original owner permission (prior V-01 limited to two growth/random files, not map). For Multi, `StandMapModel` lacks actual selectable `TreeId`, while `StandMapSource` scans Unity scene; no speculative direct integration.
- **Long-term one underlying forestry simulator** remains a research/product aspiration only; exact cross-engine tree/state, units, precision, RNG/hashes, event ordering, annual timestep and save identity require independent comparison, approved spec and owner G5/G4 **later**.

- **Feature priority:** the actual Compact30 owner-accessible established-menu+correct-forest demonstration and Multi #849 selectable/real committed 2D flow take precedence. Do not make architecture completion a blocker to either.

### B. Shared content template / browser text editor
- **Shared labels** appear in the game everywhere applicable (`Work Plan`, `Stand Map`, `Annual Review`, `Approve Plan`).
- **Scenario-specific text slots** use stable *proposed* IDs, recorded context/variant/requiredness and provenance; e.g. `[SCENARIO INTRODUCTION]` visibly present in **dev/authoring preview only**, not shipped player prose.
- **Dynamic values** (year, tree state/count/DBH, price/quote, success/failure, ecology, annual results) remain generated from real engine data, not editable figures in the text catalogue. Typed placeholders allowed only after approved validation/resolver.
- One **existing** sequenced CCF browser editor (79 pages / latest 278 records) to author/review by scenario/page; preserve original copy and separate conditional variants; export→validated reviewed Git content→approved package→typed, read-only resolver per platform; no automatic JSON→C# global replacement or fake instant Unity live modification.
