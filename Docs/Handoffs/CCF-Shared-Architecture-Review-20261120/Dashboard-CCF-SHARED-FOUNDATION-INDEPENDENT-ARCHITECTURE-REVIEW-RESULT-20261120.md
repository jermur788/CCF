## 2. What works

The family's overall direction is sound and source-honest. It keeps the mature five-rack Unity code as the 3D foundation without demanding a generic `ScenarioManager` or a rename of `ScenarioOne*`. It states plainly that diagram boxes are responsibilities, not classes (spec §3, §5). It classifies components into EXISTS IN MAIN / SIDE BRANCH / PROPOSED / DEFERRED, and every classification I spot-checked was correct (§4). It keeps the scenario selector, descriptor, save/profile identity, Compact OnGUI replacement, content policy, map ownership and engine unification as **OPEN** owner/#425 decisions (§10, plan §4 C1–C7) instead of choosing them. It also correctly refuses to treat the #820 71/71 targeted checks as proof of default launch or of a combined #836 candidate (spec §6.6, checklist 3D-008).

The Multi boundary is the strongest part. All five #730 corrections are carried with their substance intact (§4 below), including the missing `MapTree.TreeId`, the Unity-bound `StandMapSource`, and the rule that the earlier growth/random V-01 does not cover map files. The text-editor sections reuse the one existing browser tool, keep exported JSON as a draft, keep dynamic engine values out of editable copy, and keep bracket placeholders dev-only. Historical saves and worlds (v1–v24, `forest-save.json`, Legacy40, Enlarged80 Rack V2/MFM, frozen Reference Future v1) are protected throughout, and ecological calibration is explicitly out of scope. Sequencing is feature-first: plan §2 lets P1a/P1b proceed without P0, and tasks.md marks every T-row NOT RUNNING with no file grants.
