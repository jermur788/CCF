## 5. How the 2D lab should fit the overall CCF plan

**Strategic recommendation (inference): treat the 2D Multi simulator as a controlled, independent *simulation and management-rule proving ground*, while Scenario One remains the flagship 3D player experience and first external-beta delivery.** Do not replace Scenario One with Multi or turn Multi into a competing public game by accident.

### Immediate benefits to Scenario One

1. **Visibility and numerical audit:** exact source bits/roster, before/post/year snapshots, deaths and source-provenance make ecology behavior easier to inspect independently of Unity rendering and UI. Use standalone replay as one research/test reference where genuine input/model parity is established.
2. **Workflow prototyping:** Stage4 local candidates, Stage5 pending work/approval/execute state separation can expose UX ambiguity and safety defects before attempting analogous Unity changes. Compare **contracts and failure modes**, not assume code portability.
3. **Faster bounded experiments:** offline 2D environment permits short focused repetitions, negative mutations and artifact-boundary testing without every task requiring a heavy serialized Unity Editor lane.
4. **Education and long-term Stage 1 expansion:** a future 2D stand-management mode could help players learn or compare years, and larger/multiple stands might support CCF's multi-scenario forestry-first direction (D-051). **This is a potential future product direction, not owner-approved integration, a beta replacement or an accepted new Scenario One requirement.**

### Safe convergence opportunities — proposal only

- Define a cross-programme **comparison register** for overlapping concepts: stable tree identity, source/f32/f64 semantics, stand measurements, natural vs executed death, work order lifecycle, review/history, no-work replay and refusal errors. Mark equivalence **supported / different / unproven** for each.
- When a genuine shared fixture/model exists and both owners approve, run paired local offline tests on same input/seed/year and compare with defined tolerances or exact bit criteria. **Current Compact30 vs Multi P1 is NOT such a pair**.
- Share **source-independent validation patterns** (immutable accepted frame, stale rejection, atomic approvals, audit trails) where their contracts agree. Reusing code, moving save formats, importing models or changing Unity production is **separate spec/ownership/verification work**.
- Review Multi Stage5 post-Fell annual numerical evidence with Scenario One ecology experts, but do not assert Irish calibration or three-species parity from the closed pure-Sitka experiment.
- At a later intentional integration gate, decide whether the 2D viewer becomes an **optional internal debug/audit tool**, a separate released educational simulator, or a player-facing 2D companion. No such product decision has been accepted here.
