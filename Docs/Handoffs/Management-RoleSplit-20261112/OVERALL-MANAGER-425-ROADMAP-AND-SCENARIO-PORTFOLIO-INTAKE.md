## 4. Practical versus ambitious programme choice

| Decision dimension | Lean forestry-depth five | Ambitious site/estate five | Manager assessment |
|---|---|---|---|
| Learning order | Repeat forest cycle → local Oak/Beech judgement → exposure restraint → habitat/restoration restraint → multi-age sustainability | Plantation → wet-site pioneers → storm consequences → Atlantic restoration → multiple managed compartments | **Lean first**; less simultaneous novelty and easier attribution of consequences |
| New species | Sitka/Oak/Beech first; extra species only when a scoped lesson needs them | Scots pine, downy birch, alder and native minor trees early | Ambitious requires new species-data/economy/art and validation; existing research closure is not production code |
| Site and climate | Author physical context and known ordinal constraints; add causal rules only where critical | Spatial hydrology, mixed wet/open habitats, calibrated storms and restoration processes | Ambitious research/verification debt **High**; don't imply Irish parcel-specific probabilities |
| Save/runtime | One independently identifiable, persistent forest per scenario | Several simultaneous managed stands with common budget in Scenario Five | Estate system imposes portfolio UI, world advance, scheduling, shared accounting and cross-stand persistence |
| Audience and replay | Small owner/managers; meaningful alternative long-term stand outcomes | More visual variety, land-use breadth and portfolio complexity | Both attractive; first five should prove core forestry depth before broader owner portfolio |
| Stage boundary | Five independent Stage 1 forestry cases; later Stage 2 land management | Temptation to blur into multi-property/Stage 2 assets | Keep accepted D-051 Stage 1-first boundary |

**Ambitious alternative remains genuine**, not rejected: Wet-Edge Pioneer Forest teaches site matching and native/open-ground management; Storm-Broken Ridge supports real risk/salvage; Atlantic Woodland Recovery includes invasives and ecological continuity; Patchwork Holding allocates time, cash and decisions across multiple independent parcels. Admit the extra dependency stack rather than presenting the two sequences as equally inexpensive.

## 5. Reusable system map: develop abstractions only when the second scenario proves need

**A. New scenario identity and isolation (first cross-scenario architecture gate).** Before Scenario Two code, inspect the actual current definition/scene/save controller and decide the narrowest stable scenario ID, world ID and save-slot boundary. Each authored world needs its own initial inventory, scenario objectives, economy defaults, graphics and save history. Migrations must preserve Legacy40 and frozen Reference Future v1 exactly. Avoid silently assigning newer world IDs to old saves. One proof-of-play against current Scenario One plus one new world is more valuable than building a generic five-scene framework in advance.

**B. Data and behaviours separated from forest presentation.** Keep annual authoritative tree state and work resolution separate from UI/graphics; use scenario-specific species, site constraints, narrative and assets rather than hardcoding Irish/Scenario One assumptions in a shared global engine. Confirm with source inspection which supposedly shared calls are currently ScenarioOneManager-bound before deciding to extract adapters. Do not rename Scenario One fields to generic names as a substitute for sound tested behaviour.

**C. Species and occupancy.** Preserve pure-Sitka model, old saves and ordinal mixed-species density validity. Oak/Beech depth parity is not evidence of equal measured Irish precision. An expanded roster (Scots pine, downy birch, alder) would need an explicit evidence-to-spec matrix, suitable site rules, juveniles, crown/light behaviour, timber/economics and render assets. Species Evidence Closure says initial parameter design is possible with explicit abstractions; this does not approve new coefficients or playable species. Do not import central-European mixture bonuses or impose Sitka MFM sample applicability on broadleaves.

**D. Management applicability and Work Plan authority.** Distinguish physical rack access, marking, a treatment demonstration, proposed treatment and actual executed work. MFM V1 is Sitka-adult/currently comparable-unit specific. Any broadleaf or irregular-stand adaptation requires a new applicability/authorization contract and source review. Keep player confirmation and Work Plan approval as commitment gates. #418's plausible prescription-to-resolution provenance mismatch is **unproven in runtime**, being handled by #424; until checked, do not use grouped MFM execution coverage as an unqualified basis for a new scenario assessment.

**E. Annual observation and educational feedback.** The reusable teaching system should expose inputs, accepted work, actual events and longer-term ecology separately. Show seedlings versus recruited saplings; distinguish habitat continuity from stem age; distinguish observed mortality from model scenario forecasts. Use a small set of read-only size-class, recruitment, species mixture and financial indicators rather than a universal 'nature score'. Avoid more 3D UI than the player can comprehend.

**F. Hazard/site/long-term models.** StormModel1 is dormant by default. New site/moisture/wind state should be independently scoped, versioned and safeguarded; a scenario label cannot turn its inactive code into verified gameplay. Active storms, wetland hydrology, rhododendron persistence and epiphyte continuity are each SPEC REQUIRED and should be introduced only when a player-visible lesson justifies them.

**G. Shared economic data.** Keep current and historical timber prices/grants as scenarios or dated observations, not immutable Irish long-run species values. Separate saved transactions from projections. An estate-level common ledger is **not needed for independent scenarios** and should be postponed.
