**Major 1 — stand size and fixture origin.** The pinned source supports Legacy40 = **40 m/0.16 ha** or Enlarged80 = **80 m/0.64 ha**, not a 50 m parity stand. The original 50 m quarter-ha P0 synthetic fixture (three separated trees) can be declared as a **Legacy40 sparse wiring control** with centred ±15 m positions and actual source area **0.16 ha**, explicitly different from its P0 0.25 ha identity; never call this source-parity in area or sufficient density calibration. The future source owner must verify actual 40/80 scene geometry and, for Enlarged80, approach-path effects. Update N05, REQ-D11, spec/plan and decisions without inventing new fixture bytes.

**Major 2 — independent trust anchor.** The P0 co-located `MANIFEST.sha256` is not enforced by the P0 catalog and is replaceable with the fixture. Specify a reviewed, **P1-owned compiled/configuration trust table** of original fixture ID, complete file SHA-256, canonical P0 snapshot hash and pinned P0 source revision. Runtime imports compare to that table; the P0 revision is provenance metadata, not an impossible runtime Git check. A fixture+manifest forged consistently must still reject (N01, REQ-B08). Distinguish SHA integrity for trusted bytes from authorship signatures.

**Major 3 — correct pre-growth competition observation.** `GetCompetitionIndex` may lazily recalculate CI if invalidated; mortality deletes the victim's cached CI. A post-year getter can therefore show a post-growth/post-death value rather than the CI that caused growth/suppression. Capture **pre-step CI for every living ID**, using the intended competition update path with storm 0 and fixed configuration, before any annual state change; capture actual source S/roll/cause at evaluation time (never reconstruct a dead victim from post-mortality getter). Safely compare post-step survivors' cached entries **without invoking recalc** and include an instrumented versus uninstrumented same-Editor no-perturbation control. Future source owner confirms precise implementation; this docs-only revision claims no actual capture. Add N03 and REQ-C13 negatives.

**Major 4 — faithful approval-load choice.** The proposed unconditional `SessionLoaded` audit record is **NOT** existing P0 semantics. P0 on load appends only `PlanStale(SessionLoaded)` for each open approved/pending plan, and none when no such plan is open. The conservative review proposal should **remove unconditional load-audit emission**, so the drafted Option 1 genuinely describes P0 behaviour, while retaining the future owner's right to choose a distinct Option 2. If the author instead proposes a new audit variant, label it separately and do not misdescribe it as P0; document the corresponding Mode A identity test difference explicitly. Across four C-1A register copies and Mode A/B/REQ-E12/N09/N10, leave **C-1A OPEN**. No approval bypass or P0 source edit.

**Minor A — size/capacity.** At a borrowed P0 20,000-tree and 64-MiB ceiling, 10 long typed per-tree datums can fill the budget within a small number of years; reviewer ~16 MiB/year is **estimate, not measured**. Provide an explicit per-tree-year and 1/10/40-year budget, tradeoffs full per-ID versus compact annual hash/discrete-event archive, practical model limits/fail-closed case (N02). Do not claim P0 ceilings automatically govern a separately owned P1 service.

**Minor B — crown effect.** In the constrained adult growth/mortality source route crown affects crown/canopy outputs but is not an input to CI/DBH/height/density natural death; mark source-derived, not universal CCF rule.
