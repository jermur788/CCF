## Required changes — F-1 to F-5

1. **F-1 — FIFO/host hang:** `src/Core/LabDataStore.cs` incorrectly treats a directly placed named pipe `.lab-data/pipe.sitkalab.json` as a regular file; listing includes it and reading blocks the host while `st.Gate` is held. Ensure only safe regular files are offered/read and a special file cannot block the server. Test an actual local FIFO in the data root, including concurrent `GET /api/state`, with bounded timeouts and no external process left running. Preserve ordinary lab save round trips.
2. **F-2 — symlink race:** the check at `LabDataStore.cs:108-111` and later `File.ReadAllBytes` are separate and can be raced. Reviewer demonstrated thousands of outside-file reads under concurrent same-user rename/symlink swapping. Enforce fail-closed **at open/handle** against symlinks and nonregular file types; no outside bytes may be opened or returned, including under adversarial swapping. Use OS-appropriate robust APIs or a clearly documented platform restriction and tests. Merely adding another pre-open `LinkTarget` check is **not sufficient**. Verify the actual handle is a regular file and constrain it to the trusted directory; consider file descriptor based `openat`/no-follow where appropriate, with honest portability documentation. Ensure no hanging FIFO, hardlink bypass, or alternate path through save listing. Keep P0 loopback-only and `.lab-data` isolation.
3. **F-3 — misleading test:** fix `SymlinkAppearingAfterListing_IsStillRefusedBeforeOpen` so it actually tests the per-entry protection it names, or rename it honestly. A test claiming to prove race safety must actually exercise the dangerous interval and fail on a deliberately weakened guard.
4. **F-4 — layered guard test gap:** add targeted independent tests or crafted-history probes to catch X01, X06, X08, X16 and X22 in the review (redundant PlanStale, reservation and store checks); do not remove layered protections just to make mutants fail. Keep all 17 existing mutations green; if an inner check is provably unreachable, explain why and choose a realistic test seam instead of manufacturing fake coverage. Include forged hash-consistent illegal events and public API paths. Avoid weakening validation.
5. **F-5 — atomic save failure:** ensure `WriteAtomic` removes only its own temporary file if rename/move fails (e.g., target is a directory), never removes or overwrites unrelated data, and returns a controlled HTTP error rather than unhandled 500 where appropriate. Fix `Deny()` response codes to correspond to status (405, 413, 415, 500 etc.). Test error body and leftover files.

**F-6 — spec wording:** The approved spec says `hand-audited` for all fixtures, while only the 3-tree oracle is hand-computed; the 162/2,000-tree stands are formula-generated with deterministic regeneration.
