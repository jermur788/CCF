## 3. Mandatory bounded code and test repairs

**R1 — F-1: direct FIFO/special file hangs a host request.** \`src/Core/LabDataStore.cs\` currently uses path-based \`FileInfo.Attributes\` to decide if a file is regular, and \`File.ReadAllBytes\` can block on FIFO. Reproduce with a **fake disposable** named pipe placed directly in a test-owned lab root (not any protected save): it must **not appear as loadable** and trying to load it must **return promptly without holding the global host state lock**. Reject directories, FIFO, socket, device and unusual entries regardless of safe suffix. File length limit must be applied to the **actual opened regular file**; deny reads that exceed bounded maximum. Don't just hide the entry from dropdown while leaving direct API load hang.

**R2 — F-2: symlink check-to-open race reads an outside file.** The present \`LinkTarget(path)\` check then later \`ReadAllBytes(path)\` is **TOCTOU vulnerable**; #497 swapped a symlink and observed outside bytes. Replace **check-then-open** with an OS-appropriate **root-anchored, no-follow, bounded open/read of a verified regular-file handle**, ensuring the object *opened* is the object *checked*. On Linux, a directory-handle-relative open with no-follow/nonblocking flags and a post-open file-type check is one possible solution. Do not assume a managed \`File.GetAttributes\` call after a path check removes the race. If required no-follow capability is not available on a supported host/OS, **fail closed and document runtime/platform limitation** rather than weakening the accepted save-isolation contract. The original public HTTP/UI must never be able to supply arbitrary paths, and save writes must not follow symlinks. **Hard links** are a distinct same-user file-system condition flagged by review: address or explicitly classify their limits without claiming all possible local same-user hardlink attacks are defeated.

**R3 — F-3: misleading test name.** Fix or rename \`SymlinkAppearingAfterListing_IsStillRefusedBeforeOpen\` to exercise its claimed per-entry race, or explicitly rename to the root-symlink condition it actually covers. Provide a new targeted source/IO-seam test that actually fails if per-entry no-follow verification is removed. Do not claim a path-based test proves a hostile concurrent swap unless it demonstrates that sequence.

**R4 — F-4: layered-guard mutation blind spots.** Add focused tests/forged-hash-consistent event histories that fail when the relied-on guard is removed, especially \`X01\` \`PlanStale\` stage, \`X06\` execute reservation, \`X08\`/\`X22\` store checks and \`X16\` validator double-reservation. Treat **unreachable states through public API** and a deliberately corrupt-state test seam separately. Preserve defence in depth rather than deleting checks for test optics; note any logically redundant guard whose mutation remains equivalent/unreachable and prove why. Keep the original **M17 queue-again** regression covered.

**R5 — F-5: atomic write cleanup and truthful HTTP errors.** An existing directory named like \`squat.sitkalab.json\` makes \`File.Move\` fail, leaves \`.tmp-\` debris, and produces HTTP 500. Ensure temporary file deletion on every failed atomic move, with stable error mapping and no unrelated file deletion. Correct Host \`Deny()\` error payload codes for meaningful 405, 413, 415 and 500 cases; exact mapping and response contract tested. Unsupported local file collisions should be a safe client-visible error, not leaked stack trace or silent success.

**R6 — F-6 factual fixture disclosure (documentation only).** README/test documentation must say **only the three-tree oracle is individually hand-calculated**, while larger fixtures are deterministic formula-derived, schema/manifest checked and independently recomputed.
