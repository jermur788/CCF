## 3. Required revised 2D first-rack workflow

The revised spec must establish this observable sequence, with distinguishable exact current-source state and zero hidden mutation:

```text
Current committed source (Genesis / AfterMortality; 100 exact IDs)
  -> player plans ONE 2D rack (entry/corridor/served-tree rule)
  -> explicit rack Confirm (source-bound pending rack-clearing orders)
  -> player inspects actual trees; records manual/sample judgement
  -> optional transparent comparable-only treatment proposal [G1 or DISABLED]
  -> player reviews and may approve a prescription
       (creates/reconciles PendingWork only; proposal is NEVER Fell)
  -> Work Plan displays combined rack/manual/prescription pending work
  -> separate explicit whole-batch Work Plan APPROVAL
  -> G2-proven atomic, idempotent authoritative Fell in current source-year
  -> immutable exact-year actual result and death-cause provenance
  -> next real annual ecology from actual survivors
  -> read-only prior result, newly inspected next cycle; repeat or NO WORK
```

**Two approvals:** a prescription review/approval creates pending treatment work; it is not necessarily required for **manual** work or **rack-clearing** orders. Those orders enter the same ordinary pending/Work Plan path with distinct provenance, not a secret second Fell pathway. **Only Work Plan approval commits the whole valid batch**. Rack Confirm never approves or executes; even a single-click rack authoring action cannot Fell. A displayed #805 `REMOVE_CANDIDATE` remains an untrusted reversible suggestion until manually reviewed and revalidated; Stage 4 has **no** authoritative Fell.

**Source rules:** one accepted experiment/source/fixture/model/current committed year/revision governs geometry, service and work eligibility; validate exact case-sensitive ID and current live status, original 100-tree lineage, f32/f64 where applicable, sourceKind and state parentage. Absent XY, accepted access/entry geometry or legal corridor-service basis causes explicit rack-plan **refusal and STOP for G0 technical design**, not fictional trees or silent line drawing. All duplicate target IDs across rack and manual/prescription work must be reconciled or the entire conflicting batch refused; no partial Fell. Post-execution rack geometry is locked where it has any executed removal; year-to-year later operations must not reuse old eligibility. A disabled comparator does not disable the player's reviewable manual tree work.

**Progress honesty:** distinguish `planned`, `confirmed`, `pending`, `Work Plan approved`, `executed` and `year advanced` with screen-readable states independent of red/blue alone. No “work done” badge from marks, previews, rack confirmation or a time skip. On refusal, preserve source, counts/BA, current ecology and committed history; display exact reason. Same-process replay of a successful identical execution key must return the already-applied result without additional work; a changed payload under that key or another key targeting already-executed/dead IDs is refused. No claim of durability after process restart.

**Year semantics:** distinguish `Year y work applied` from `Year y+1 biology committed`; first qualified demonstration should show source Year0 before/after approved work and a real next-year Year1 result (plus later years), while the original no-work Year0–10 oracle remains unchanged. Show biological deaths separately from player Fell, recalculated competition/BA and correct zero-live terminal behavior according to an explicit G2 source policy. Multiple cycles require a new committed source year, new sample/review, optional no-work years, and no automatic global extrapolation. Observable forest changes must be real source outputs rather than a UI count edit or relabelled old frame.
