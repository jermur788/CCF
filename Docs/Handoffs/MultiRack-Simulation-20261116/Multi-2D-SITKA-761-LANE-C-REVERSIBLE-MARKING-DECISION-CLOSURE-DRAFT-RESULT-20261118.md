## 3. Source-owned eligibility, stage and numeric precision — replacement contract proposed for C

**No C implementation may calculate, import or cache its own `isActionable` boolean by rounding DBH.** Before any optional C local mark control is enabled, a *future single Core-owned read adapter* must produce a complete `EligibilityProjectionV1` aligned with #748 F2. It is **not** a P1 work command, approval token, or existing runtime API.

| Required field | Proposed meaning and fail-closed guard |
| --- | --- |
| `observationKey` | Exactly same full `ObservationKeyV1` as the accepted current E snapshot/inspector/A callback, not an integer revision or merely year/fixture ID |
| `producer` + version | One reviewed Core read-eligibility adapter identity and numeric/code provenance; C cannot duplicate it |
| `eligibilityRuleId, eligibilityRuleVersion, ruleSourceRef` | Explicit approved mark/proposal-eligibility or work rule origin, domain and model scope; unknown if decision/review missing |
| `thresholdExact, unit, operator, conversionPolicy` | Imported source-authoritative threshold **bits/units** and reviewed comparison; the 170mm annotation cannot stand in for this tuple; equality outcome **pending approval** |
| `evaluationContext` | Complete registered tree set, observation stage/year/model/geometry/status, trusted source admission, rule applicability; static Genesis inspection alone never grants action |
| `treeResults` | Exactly one row per registered ordinal case-sensitive treeId, with current **f32 DBH cm bits**, living flag and any other rule-required source predicates, exact result `Eligible`, `Ineligible(typedReason)` or `Unknown(typedReason)` |
| `overallStatus` | `Evaluated` only if all required predicates and every row are trusted and verified against the one complete roster; otherwise `Unknown(reason)` with Mark unavailable; optional versioned projection digest cannot invent approval |
| `provenance` | Source observation and rule references; any UI indicator is a non-authoritative display of this provenance, never a Fell permission |

**Why this matters:** the frozen Year0 fixture is valid for inspection. Its **12 rows with integer `dbhMm<170` and one row exactly `dbhMm=170`** are an **initial-display annotation**, not proof of the current accepted C work threshold comparison or later execution eligibility. Year1 carries source f32 DBH cm after growth, and a Year0 integer-mm threshold badge is **not** a Year1 decision. All 100 living trees, even if under action threshold, remain part of adult growth, competition, BA/density and mortality; work eligibility is a different predicate. Do not infer "healthy" from living, CI or mark colour. Some future sources may have dead registered rows; they remain inspectable historical IDs but do not join living biology.

**Exact threshold acceptance design** (NOT results): supply three f32 inputs **strictly below**, **exactly equal**, and **strictly above** the source-approved exact threshold, with full rule ID/version and current observation key; add a fourth input that rounds to the same label as equality. Only an **explicitly approved operator** determines the equal input's `Eligible`/`Ineligible` result. Without it, all actions dependent on that policy are `Unknown(ThresholdOrComparisonUnverified)` and blocked; the UI must not quietly decide inclusive/exclusive equality. Neither C nor A performs conversion from text "17.0 cm" back to work precision.

**Known vs unsupported:**

- `Eligible` means a reviewed read-side eligibility projection for *local proposal on that observation*, and **never** actual ExecuteWork permission.
- `Ineligible(reason)` means the exact accepted rule and complete source prove the reason, e.g. NotLiving or BelowApprovedThreshold. Unsupported live/dead, class, stage or prior-work data cannot be guessed.
- `Unknown(reason)` includes missing current exact DBH, unapproved rule/operator, incomplete projection, mismatched key, unsupported source stage/domain, or untrusted producer. **Inspect remains allowed** for a valid source snapshot even when proposal eligibility is Unknown; C Mark remains disabled by the recommended conservative rule.
- Stage/diagnostic availability inherits #748 **F1**: Genesis-only CI is `NotEvaluated(StaticGenesisNoAnnualEvaluation)` rather than 0; unknown CI/BA/RD does not automatically make an otherwise valid static inspection invalid. C must not recompute CI or treat a missing annual diagnostic as a work selector. The field's source phase and numeric type must be respected if later supplied.
- The exact threshold note is independent of all-living biology; do not filter the A 100-tree roster by candidate marks or action-eligible ID count.

**Future real action boundary:** only an *independently approved* command/Work Plan service may, after explicit player plan review/approval, re-evaluate the **entire** currently reserved set under then-current authoritative forest revision, approved rule/version, session approval epoch and command-ID/idempotence policy. A stale F2 `Eligible` at drawing time is not permission to execute. Plan approval alone does not Fell; an actual validated `ExecuteWork` is the sole work operation that may change live state. Natural mortality and Fell work must remain separately recorded.

## 4. Complete observation identity, stale handling and C/A/D boundaries

#748 **F3** defines one opaque `ObservationKeyV1` whose equality covers the **entire** source/lineage record, not any display revision substitute. The future Core adapter+codec owns its wire representation; this C draft will not fabricate a hash or embed a new session UUID.

The key must semantically bind:

1. read-schema ID/major/minor and compatible version;
2. source bundle kind/ID/digest/manifest version (trusted fixture-only or qualified fixture+report, never just a path);
3. domain tag, fixture/catalog ID, fixture byte digest and trust version;
4. experiment lineage and origin generation; **StaticBundle** generation for H0 fixture-only, not a fake live epoch;
5. growth/RNG/algorithm versions, numeric policy, runtime compatibility class and exact simulation seed;
6. coordinate geometry, axes/origin, transform version and f32 stand-area bits;
7. observed ecological year, source stage `Genesis` / `Before` / `PostGrowth` / `AfterMortality`;
8. target year and exact transition ID for an actual completed annual step, typed N/A for Genesis; committed revision/frame ID scoped to generation;
9. observation provenance `FixtureOnly` / `QualifiedReportOnly` / `CommittedEngineState`; no invented durable event tip for report-only H0.

A's approved H0 inspection observer must treat `(treeId, fullObservationKey)` as **inspection intent only**. Its one selected primary ID is not a C batch toggle, not a candidate removal and not a Work Plan. In a *later separately approved C view*, the accessible case-sensitive ordinal **all-tree checklist** supplies batch selection. A retains one hit-test/primary selection/zoom/pan/HTML shell; C owns local candidate map and publishes one immutable overlay input with **(baseObservationKey, localEditRevision, ordered candidate glyphs)**. A's writer alone paints overlays; C cannot co-edit A's renderer or define a parallel pixel-to-ID mapping. A richer modifier-aware activation event is optional and still OPEN; no invented direct canvas shortcut.

## 5. Local UX transitions and visible semantics — all future DRAFT behaviour

**Five distinct concepts, deliberately noninterchangeable:**

| --- | --- | --- | --- |

Historical **natural death** is a separate recorded biological event, not a Fell, candidate mark or sale. Any dead tree remains a stable inspectable ID where the source truly supports that row.

| Undo/Redo grouped action | Same full key, EDITABLE and valid stack | Restore preceding/subsequent **candidate map only**; new edit clears redo | None |

**Local grouping and cancellation:** one explicit Mark/Unmark action spanning N IDs is one undoable UI operation. Repeated Mark of an already-valid candidate and Unmark of a non-candidate are idempotent UI no-ops, not duplicate history. After Undo, an actual new edit drops Redo. Escape may clear inspection/search focus or close a confirmation, **but never discards candidate marks without confirmation**. Discard is a UI state reset; it is not a canonical work-plan `Cancelled` event. Mark state is not retained across browser reload/save unless a later separately approved D contract exists.
