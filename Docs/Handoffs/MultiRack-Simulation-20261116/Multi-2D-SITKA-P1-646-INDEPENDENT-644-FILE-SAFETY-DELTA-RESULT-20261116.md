**Why it matters:** the packet specifically requires scrutiny of inherited/undecodable FDs and fail-closed unresolved mutating paths. [Analyzer header lines 1–13](https://github.com/jermur788/CCF/blob/33c0506990eefb6bea4277a553d2fe38408bb353/Tools/MultiRackSitkaP1Lab/tests/l4_analyze.py#L1-L13) claims unresolved relative mutations fail closed, but the new fd-based coverage can silently miss a traced mutation when descriptor decoration is absent. Original-P0 L2/L3/L3+ reported checks reduce risk of persisted changes, but they cannot exclude transient writes that are later reversed.

**Smallest bounded fix:** for all fd-only mutating operations, explicitly require a **resolved descriptor path**; if absent, add an `UNRESOLVED` entry and fail the L4 gate. For other mutator forms, likewise treat a successful mutation with neither a target path nor reliable resolution as unresolved. Add synthetic parser-regression lines with bare and decorated fd forms and a read-only control. Independently demonstrate the corrected analyzer refuses the bare-fd trace and accepts the resolved benign control; then rerun the bounded author L4 trace on the same owner lane. **Do not** repeat all #643 fixture hashes or enlarge to Host/saves/Unity.
