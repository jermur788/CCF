## 3. Strengths and positive feedback

1. **One-shot task packaging is effective for bounded native features.** #789, #811 and #814 show implementation → independent nonauthor review → focused fixes → verified evidence → one durable handoff can be orchestrated in one run, reducing Manager dispatch traffic. One-ticket/one-result is a good default when source and physical boundaries are explicit.
2. **Model specialization and provider independence add value.** DeepSeek handled setup/orchestration and routine source/UI implementation, while Claude nonauthor review found substantial high-value defects (#811's ignored project file, frame validator reach; #789 survived mutants). The Oct run used stronger models on high-consequence save/determinism work instead of spending frontier subscriptions on mechanical operations.
3. **Source and machine safety improved when preflight was explicit.** Separate native worktrees, read-only restored baselines, immutable hashes, narrow file allowlists, serialized heavy operations, and 'no merge' boundaries prevented inadvertent collateral changes. #810 avoided unneeded environment work; #811/#814 stayed additive.
4. **Actual qualification at the artifact boundary matters.** Shipped HTML embedded-package tests and `file://` Edge/CSP/no-network checks caught integration/packaging issues the JS source suite alone would not establish. Forced offline rebuilds and archive restore rehearsals improve reproducibility.
5. **Failure classification and conservative acceptance work.** The ledger recorded quota exhaustion as a capacity event rather than code failure, and identified stale Unity harness expectations versus actual production defects. Explicit IMPLEMENTED / REVIEWED / QUALIFIED / INTEGRATED / ACCEPTED kept local results from being misrepresented as main-qualified release.

## 4. Problems, drawbacks, and risks (evidence ranked)

### A. Provider quota and context telemetry — **observed limitation**

Oct user reported ~13% of a five-hour OpenAI B window; actual provider later produced Subscription Sharing usage-limit error mid-turn. Claude quota/reset and the exact remaining OpenAI reset were unknown. #789 later used a second authenticated account when the original Codex account was exhausted. **Improvement:** prior to dispatch, record provider pool/auth state, estimated capacity-to-completion, observed reset, contextual work checkpoint and fallback branch; require a pre-exhaustion durable commit for long tasks. Never infer remaining capacity from authentication presence, nor bypass provider quotas.

### B. Reviews can be genuine but the final formal verdict can diverge — **observed #814**

A re-check that confirmed nine corrected findings still returned **NEEDS CHANGES** because the evidence record pre-stated an approval not yet received. **Improvement:** immutable reviewer-response receipt, report field `finalReviewerVerdict` sourced from the received message only, no future-tense text disguised as historical result, automatic mismatch check and precise distinction **Manager APPROVED LOCAL despite nonauthor NEEDS CHANGES**. Avoid optimistic verdict templates.

### C. Proof scope may not include everything that is compiling — **observed #789 / #804**

Narrow private exported source depended on public Asset compiler inputs and an unrelated scratch full checkout; source files and qualified executable state were not trivially identical. **Improvement:** preflight a full compile/transitive input manifest and a candidate-to-scratch provenance receipt *before* Q or before claiming build entitlement; track separate source read scope, write scope, build-copy scope and test scope, not a generic 'permission granted'. A locally passing suite is not proof of public/main authority.

### D. Physical Ops custody may be unavailable — **observed #811/#814**

The external board was unmounted. Workers checked local ownership and preserved unmodified external state, but couldn't re-read the named external lease. **Improvement:** surface physical Ops availability as a distinct gate with supported fallback/exception policy; either secure a manager-approved restricted local-only lane or block. Don't silently equate a local process scan with a signed shared physical lease.

### E. A single run may hide operational edges — **observed #810/#811/#814**

Restored worktree integrity did not imply runnable SDK/build qualification; in #811 the SDK used latestPatch; source-positive test suites did not complete screen reader/touch/200% and independent gameplay. **Improvement:** risk-tiered exit matrix covering *artifact boundary, runtime, accessibility, independent reproduction and release*, with PASS/FAIL/NOT RUN and exact candidate head. Default 'local candidate' when independent developer and UX gates remain incomplete.

### F. Archive/restore and clean checkout testing are necessary — **observed #789/#811**

#789 first restore exposed a real archive incompleteness. #811 first nonauthor review found the exporter `.csproj` gitignored, so it would fail on a clean checkout despite local build success. **Improvement:** make `git ls-files`, clean/extracted ephemeral clone, `git fsck`, first-time build and restore rehearsal standard for artifact-producing tasks, scaled to risk.

### G. Specification semantics and owner priority drift — **observed #812/#816/#817**

A prior phrase “one rack” was turned into a full physical rack-geometry requirement even though owner later clarified it meant a single undivided management area. **Improvement:** before expensive multi-file specs or code, maintain a small *owner decision semantic ledger* with what is explicitly instructed vs agent inference, confidence and cheapest clarifying question for high-impact ambiguous noun/scale choices; apply latest direct owner instruction over stale handoff and issue comments. When a superseding decision arrives, mark all dependent packets and review findings superseded and stop obsolete work.

### H. Excessive coordination overhead for document-only work — **retrospective inference**

#812 author → #816 reviewer → #817 four-file correction is defensible for cross-system source-risk work, but could be streamlined with one review-and-bounded-fix loop when the scope/owner direction is stable. Keep independence by retaining a separate reviewer session, not by necessarily creating serial mini-issues for every editorial fix. Ask the skill maintainer to evaluate coordination tokens and real wall time before relaxing any independent-review safety gate.
