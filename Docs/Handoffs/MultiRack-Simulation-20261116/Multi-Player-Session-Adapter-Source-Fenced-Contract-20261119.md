## 2. Proposed smallest safe session interface — NOT PRESENT IN G2

**Design rule:** implement the minimal read/command seam **inside the existing `AnnualContinuation.sync` lock**, operating on one `WorkRoot`, never by concatenating public `Frame`, `CurrentToken`, `HasUnexecutedWork` or a second UI-maintained roster across separate calls. The adapter may be a thin in-process public facade over an internal continuation; it must not publish an internal mutable continuation to the browser or start a parallel engine.

**PROPOSED view record** (names provisional; no C# source granted):
- `PlayerSessionView { SessionIdentity, Source: WorkSourceToken, Frame: CommittedFrame, Pending: IReadOnlyList<WorkOrder>, ApprovedUnexecuted: WorkPlan?, PlanStateRevision: long, Events: IReadOnlyList<WorkEvent>, SourceAvailability }`.
- `Source` is constructed by `Token(root)` while the **same** lock builds `Frame` from `root.Snapshot`, `root.WorkRevision`, `root.Events`, copies actual `root.Pending` and approved immutable `root.ApprovedUnexecuted`. `Frame.Events` and `Events` must refer to the **same committed ledger**; duplicating them for transport is optional, not a second history.
- `Frame` retains actual `Trees`, `Stand`, `EcologicalYear`, `AnnualRevision`, `WorkRevision` and exact source hashes. Copy to immutable/read-only containers before returning; no caller-owned mutable collection may change the root or view. The approved plan must not be accepted back by reference from an untrusted browser without session-bound lookup and validation.
- `SessionIdentity` is a **proposed opaque in-process session handle**, not a source claim, persistence key or authorisation token. Reject commands routed to the wrong or abandoned continuation; the source token alone does not identify the process instance. This introduces no Host/network/session durability guarantee.
- **Proposed extra `PlanStateRevision`:** an ephemeral monotonic counter in the same root, increased on each successful Add/Remove/Approve/Cancel and on any unexecuted-work cancellation at year advance. Do **not** change `ContinuationSnapshot`/annual JSON, the existing `WorkSourceToken` shape, or `WorkRevision` semantics. Commands include expected `PlanStateRevision` in addition to the mandatory full source token. Alternative exact pending/approval state fingerprint requires independent ABI review; choose one and test it before implementation. A stale queued editor otherwise has the same source token after another editor approves/cancels.
- Source read admission must be only an actually **committed** Genesis or AfterMortality frame as allowed by the future accepted read boundary; `#805` candidate read/spec remains DRAFT and is **not** evidence that this bridge already exists. Before/PostGrowth diagnostics and reversible REMOVE_CANDIDATE may be displayed separately but are never legal work-source state.

**PROPOSED command contract** (pseudo-signatures, *not observed methods*): all mutate operations take `SessionIdentity, expectedSource: WorkSourceToken, expectedPlanStateRevision` plus their action arguments, under **the exact same lock as the authoritative mutation**. The complete `WorkSourceToken` means all 12 fields, exactly:
`Domain; FixtureId; FixtureFileSha256; FixtureContentHash; ManagementScopeId; EcologicalYear; AnnualRevision; WorkRevision; RngModelVersion; GrowthModelVersion; P1AlgorithmVersion; ActionEligibleDbhThresholdMm`.
Exact ordinal/case-sensitive identity comparison and same-session binding are mandatory. No reduced `year + annualRevision` comparison; no floating-point digest substitution. For every refusal, return/propagate actual `P1Refusal.Code` or a separately specified adapter `P1Refusal` code, never silence it.

| Player command (PROPOSED facade) | Same-lock conditions and effect | Response and source guarantee |
|---|---|---|
| `ReadSession()` | Acquire `sync` once, snapshot current root, build view fields together | One internally consistent committed view; no work. |
| `AddPending(expected, queueRevision, treeId, reason)` | Check complete token/session/queue revision **before** exact case-sensitive live lookup. Call ordinary pending path once. Require explicit nonblank reason, no approved plan, no duplicate. | Updated atomic view with one real `WorkOrder(TreeId, Fell, Reason)`; **zero Fell/event/year/work revision**. Browser draft alone never adds it. |
| `RemovePending(expected, queueRevision, treeId)` | Same fences, exact pending ID; refuse absent ID, approved state or stale view | Updated view, order removed; no biology. |
| `Approve(expected, queueRevision, planId)` | Same fences and nonempty pending; **distinct player approval**, stable plan ID bound to source/orders | Return actual `WorkPlan` and view showing approved-unexecuted state; move pending to approved with zero Fell. |
| `CancelApproved(expected, queueRevision)` | Same fences; explicit player cancellation of an actually approved-unexecuted plan | Approval cleared; do **not** silently restore orders to pending or claim executed-work rollback. |
| `Execute(expected, queueRevision, approvedPlanIdentity, executionKey)` | Fence same-session full source and queue state; resolve the **actual** approved plan in the root (not a client-fabricated `WorkPlan`); require exact approved identity/immutable orders; call existing `Execute` without exposing `beforePublish`. All live/case/duplicate/all-live checks before one root publish. | Return `WorkExecutionResult(Event, Replayed, ...)` + freshly read **same-year** view. One true source event, one workRevision increase, no annual year jump; zero partial Fell on refusal. |
| `Advance(expected, queueRevision, consentToCancelWork)` | Fence complete source/session/plan state; use **modern** four-fence path `Advance(expected.EcologicalYear, expected.AnnualRevision, expected.WorkRevision, consentToCancelWork)`, never legacy two-clock overload. With pending/approved work, no consent refuses; with explicit consent stale-cancels all and calculates real following-year biology. | Actual `AnnualReport` and new committed Year+1 view; zero Fell on consented cancellation. WorkRevision unchanged by annual biology; old work plan cannot reappear. |

**Mutation ordering:** do not read view then release lock and only afterwards validate stale tokens: all checks and the authoritative root mutation belong to one serialized operation. UI drafts, highlighting, local tree selection and screen state can remain outside engine, but are never `Pending` or `ApprovedUnexecuted`.

**Important replay exception requiring explicit engineering:** a legitimate same-process retry of `Execute` with the **pre-Fell expected token** will no longer match current work revision. A fenced facade may *only* return an already recorded `Replayed=true` receipt under the same lock after confirming matching session, exact execution key, original full token and identical approved payload; this is a **read-only idempotency exception**, never authority for another Fell. Other mismatches refuse. The existing `Execute` replay lookup checks stored source + orders but **does not include `PlanId` in its equivalence test** (**A-2 advisory**). Thus a robust cross-plan replay contract is **NOT IMPLEMENTED**; do not claim it or silently change A-2 during #846. A later adapter implementation must either enforce matching `Event.PlanId`/plan identity before returning a replay or return a precise documented blocker for Manager adjudication. No crash-restart replay guarantee.

## 4. Event/advance ordering and minimal demonstrable trace (no fabricated runtime observation)

**Use actual fields, not invented measured values or a fixed future-living ID.**

1. `ReadSession()` returns `Frame.Trees`, `Frame.Stand.LivingCount`, `Frame.Stand.BasalAreaM2PerHa`, complete `Source`, empty or actual `Pending`, `ApprovedUnexecuted`, `Events` and `PlanStateRevision`. Choose a **currently** `AnnualTree.IsLiving` row's exact `TreeId`; display `XM`, `ZM`, `DbhCm`, `HeightM`, `CrownRadiusM`. A local form selection is not yet work.
2. `AddPending` with complete expected token + plan-state revision and reason creates one `WorkOrder(Action=Fell)`. `Approve` after fresh read yields a `WorkPlan(PlanId, Source, Orders)` but **`Frame.EcologicalYear`, `AnnualRevision`, `WorkRevision`, `Events` and living stand are unchanged**.
3. Separate `Execute` returns a true `WorkExecutionResult`: `Event.EcologicalYear` is the **same** work year; `Event.WorkRevision` increases once; `Event.Fells` contain `FellRecord.TreeId/Cause/Mechanism/Reason/PlanId/ExecutionKey`, with `Cause="fell"` and `Mechanism="manual-work-plan"`, not natural `AnnualDeath`. Re-read shows selected actual `AnnualTree.Death`, changed **source-calculated** count/BA and exactly one new `WorkEvent`; do not call this an annual advance.
4. Refresh token **after Fell**, because same ecological year and `AnnualRevision` do not imply freshness. With no unexecuted work, modern `Advance` uses `expected.WorkRevision` from that read and yields `AnnualReport.YearBefore`, `YearAfter`, `Before`, `PostGrowth`, `After`, `Trees`, `Deaths`. `report.Before` uses actual post-Fell living survivors, `Frame.EcologicalYear`/annual revision now advance, work revision stays as after Fell, and the historical same-year work event remains read-only.
5. Fresh Year+1 read supports another per-live-ID decision (or a no-work year); old Year-y source token, old approved plan or UI draft cannot be re-used. A no-work Year0–10 run must preserve the **existing ten golden digests** with no Fell.

**Historical ordering:** committed same-year `WorkEvent` is appended at `Execute`; `AnnualReport` for the following year is produced later by `Advance`. The root stores typed work events, **not** persisted annual report history; a UI may display a session-local report from a completed advance, labelled as such, but may not fabricate a durable historical report log from event counts. Read-only "previous/current/proposed" must distinguish actual committed events and transient proposals.
