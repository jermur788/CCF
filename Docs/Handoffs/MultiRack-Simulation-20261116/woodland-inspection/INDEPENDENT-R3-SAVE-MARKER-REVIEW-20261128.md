## Source ordering

- **Survey and Save.** Once the body is read, Save takes the host lock and checks the inspection state before slot work. Save then takes the slot gate, captures the fenced save and marker, writes the slot and publishes the marker before releasing either lock. Survey load commits under the same host lock. If survey load commits first, the Save refuses before slot metadata or marker work. If Save commits first, the survey can open only after the marker is published, and a playable view sampled after opening reads the published state under that lock. [Save](https://github.com/jermur788/CCF/blob/9413595bd257c11be141edcabfd014ee87350726/Tools/MultiRackSitkaP1Lab/src/Ui/MultiApi.Saves.cs#L109-L156) | [Survey load](https://github.com/jermur788/CCF/blob/9413595bd257c11be141edcabfd014ee87350726/Tools/MultiRackSitkaP1Lab/src/Ui/MultiWoodlandInspection.cs#L178-L191) | [Playable view](https://github.com/jermur788/CCF/blob/9413595bd257c11be141edcabfd014ee87350726/Tools/MultiRackSitkaP1Lab/src/Ui/MultiApi.View.cs#L42-L69)
- **Newer same-slot Save.** Each successful Save publishes before a subsequent Save can enter the host lock. The second Save captures the host record already updated by the first and publishes its own marker before unlocking. The old schedule in which both saves capture one host record and the later file write loses its marker is therefore excluded. `MarkPersisted` re-enters the same C# monitor on the owning thread. `ReferenceEquals` succeeds because the host record captured under that monitor is still current and the synchronous slot helpers do not update it. Nested acquisition of the slot monitor is also reentrant. [Host marker](https://github.com/jermur788/CCF/blob/9413595bd257c11be141edcabfd014ee87350726/Tools/MultiRackSitkaP1Lab/src/Ui/MultiSessionHost.cs#L44-L64) | [Slot monitor](https://github.com/jermur788/CCF/blob/9413595bd257c11be141edcabfd014ee87350726/Tools/MultiRackSitkaP1Lab/src/Core/Phase1/Phase1SaveSlots.cs#L252-L272)
- **Refusals and write outcomes.** Survey refusal, SlotExists, fence rejection and a slot write that throws all bypass publication. A normally returned write still publishes for both `DurablyCommitted` and `ReplacedDurabilityUnconfirmed`, preserving the existing semantics for a successful rename whose directory flush could not be confirmed. The API preserves both response status strings. [v3 write](https://github.com/jermur788/CCF/blob/9413595bd257c11be141edcabfd014ee87350726/Tools/MultiRackSitkaP1Lab/src/Core/Saves/SaveV3Slots.cs#L58-L105) | [v2 write outcome](https://github.com/jermur788/CCF/blob/9413595bd257c11be141edcabfd014ee87350726/Tools/MultiRackSitkaP1Lab/src/Core/Phase1/Phase1SaveSlots.cs#L176-L188)
- **R1, R2 and response.** The commit-time inspection guard remains before any slot work. The survey response still comes from the entry committed by that request. Recover still takes host before slot, and the storage helpers do not acquire the host. Save still increments `savesWritten`, decodes the response header and serializes the response after releasing both locks. The refusal response is also written after leaving the lock.
