## 2. Official Windows policy: what is supported and what is not

**Microsoft's Smart App Control FAQ** says the cloud service first predicts reputation; if it cannot confidently allow a binary, valid trusted code signing is another route. Unknown unsigned code can be blocked. It explicitly states **no per-application exception/bypass** and directs users toward the developer signing the app. SAC is distinct from Microsoft Defender antivirus, reputation-based SmartScreen checks, separate managed App Control for Business/WDAC policies, Zone.Identifier and .NET error handling; making an antivirus exclusion, unblocking the download, changing file permissions, or allowing an app in another security UI is not shown to release this SAC Code Integrity denial. [M1][M2][M3]

A **legitimate publisher-signed official Unity package** is the right class of fix: vendor issuance must encompass the actual denied Bee assembly and any other needed unsigned managed/native load targets. It must be obtained through Unity's official distribution/channel, retain the vendor's normal integrity/provenance and pass **actual host SAC On execution**. Do **not** self-sign, repack or replace the installed DLL or use downloadable “DLL fix” mirrors. Further generated/JIT compiler DLLs might independently be denied: community members report Burst-generated local DLLs; that is a **plausible secondary issue, not verified by #611 beyond its initial Bee blocker**. [U3][U4][M2]

### SAC OFF / return-ON documentation contradiction

- **Microsoft's currently accessible SAC FAQ** (retrieved 16 Nov; page has no reliable visible authored/update date) says **recent Windows updates permit re-enabling SAC without a clean install**, if that option is available on the device. It still describes specific states (e.g. optional diagnostic data disabled) requiring reset/reinstall. [M1]
- **Microsoft's Windows Security “App & browser control” page** says once evaluation completes or a user manually chooses a mode, they cannot return to **Evaluation** without reset/reinstall. That is specifically an *Evaluation* claim, not definitive proof that Off→On is unavailable on all newer builds. [M3]
- **Microsoft's separate developer overview** (shown last updated 6 Oct 2026 in search) still describes clean-install activation as a requirement, while **Microsoft's developer test/signatures page** states setting SAC On or Off through Windows Settings is a **one-way operation** unless currently in Evaluation. The latter describes a registry-for-testing mechanism with explicit security-risk warnings; **this project must not use or reproduce that mechanism**. Together these are material documentation inconsistencies. [M2][M6]
- **Conclusion:** the general current FAQ suggests some later supported GUI re-enablement, but no device-specific Windows edition/OS build/KB and switch-back control check was available to this research. **Do NOT assert that Off→On is reversible on DESKTOP-DL1BQI7**. The prior observed On state does not guarantee the Off→On action would be available afterwards. Also, SAC is an additional layer alongside Defender/SmartScreen; disabling it reduces protection even if these continue to work. [M1]

**Permissible future READ-ONLY device check** after Manager/owner approval: capture `winver` edition, version and full OS build/UBR; Windows Update history with relevant KB; `Settings > Privacy & security > Windows Security > App & browser control > Smart App Control settings` screenshot showing On/Evaluation/Off and enabled or greyed controls **without touching any toggle**; Windows Security status; and, if necessary, the official read-only `citool.exe -lp` reporting current enforced policy. ## 5. Windows isolation and alternate OS routes — practical reality

Windows requires a supported GPU/API and hardware vendor drivers; **8 GB RAM is recommended at minimum**, actual graphics depends on the project. This is stronger and narrower than Windows itself offering a virtual GPU. A VM that launches Unity is still **outside Unity's stated supported Editor environment**, and native-looking 720p/1080p screenshots would need independent fidelity checks. [U6]
