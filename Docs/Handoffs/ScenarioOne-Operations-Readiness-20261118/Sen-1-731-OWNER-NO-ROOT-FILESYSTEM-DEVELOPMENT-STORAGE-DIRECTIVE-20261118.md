## Non-negotiable rule

**Do not create, generate, install, stage, compile, render, cache or run developer scratch output on the OS root filesystem.** Do not create new worktrees, repositories, build products, cloned asset sources, verification folders or package downloads under root-backed `/home/jer`, `/tmp`, `/var/tmp`, `/opt`, `/usr/local`, `/root` or other directories without independently verifying their backing mount. **Filesystem backing**, not a pretty path string, determines compliance. No bind mount/symlink escape into root.

Explicitly includes native TG Fork / OpenCode, T3, Codex and Claude logs/caches/temp generated by development sessions; Blender .blend/.blend1/autosaves, intermediate frames, image and import caches; Python pycache and temporary directories; Unity Editor/Library/cache/build/Logs; package managers, compilation outputs, and any scratch verification. Do not blindly change `HOME`, global configs, cached provider authentication or user-owned permissions to move logs. **Where tool internals cannot be proved root-free, stop launching further development processes and escalate at a safe checkpoint.** Incidental system writes outside program control cannot be claimed zero without a trace.

**Current observed risk:** Live #785/#786/#787 workers independently report intended art source/worktrees under `/media/jer/Files`, an ext4 Files mount; they report Files itself **95–96% used** and around 23–27 GB free at their recorded times. These are **worker GitHub receipts**, not Manager direct mount reads and not a blanket admission. Do not assume `Files` has ample remaining room or is on a separate *physical drive* merely because its path differs. **ZX20 Ops mount-identity checks are still broken and ZX20 cannot be selected as fallback without lawful, current physical checks.**

## Required live preflight for every development worker and parent

1. **Inventory before start / before more heavy work**: read-only `findmnt -T /`, `findmnt -T <candidate>`, `lsblk` for root and target block identity, realpath/owner/mode, `df -B1 /` and `df -B1 <candidate>`, available bytes/inodes, actual physical lane owner, processes and already-dirty worktree. Do not use a stale GitHub snapshot to prove host mount/custody.
2. **Reserve a unique real non-root output area** on a genuinely independently mounted, writable data filesystem, currently `/media/jer/Files/CCF/Operations/**` for docs worktrees and separately `/media/jer/Files/CCF/Verification/**` for scratch if capacity is still safe; use ZX20 only if its own current Ops and custody are lawful. A path under `/home/jer` is prohibited unless mounted separately and proven not to occupy root.
3. **Before child process starts**: set and verify process-scoped `TMPDIR`, `TMP`, `TEMP`, safe `XDG_CACHE_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME` as applicable, Blender temp/autosave/render caches, Python cache/bytecode suppression or routing, and the explicit output paths **under each worker's approved non-root directory**. Record actual process-visible values. Do not relocate provider credentials or copy configuration just to pass a check; if the process still writes to root by default, HOLD rather than ignore.
4. **Capacity**: Files is almost full; maintain **at least 10 GiB actual free** at all times for current original asset scratch development, with a stricter floor if active other users need it. Parent caps each child and watches real bytes/free space before/after heavyweight phases and stops **before** crossing the floor. Do not clear caches, build folders or another worker's data without explicit file-by-file owner approval and rollback.
5. **Protect current work**: do not terminate owned processes, abandon a worktree, stash/reset/clean or move/edit a registered branch, overwrite user Primary dirty work or change Ops board/lanes config to free space. If an already running worker needs to pause, let it reach the next safe checkpoint, preserve and hash any output, mark claim BLOCKED and obtain new custody before relocation.
6. **Evidence for every substantive handoff**: include realpath, mount/block identity, root and target free space, tool environment and temporary output paths, source/render file hashes/size, independent review, any observed unavoidable root writes, actual stop decision and honest uncertainty. A GitHub document alone does not prove physical compliance. Do not mark all-root-writes-excluded unless actually measured.
