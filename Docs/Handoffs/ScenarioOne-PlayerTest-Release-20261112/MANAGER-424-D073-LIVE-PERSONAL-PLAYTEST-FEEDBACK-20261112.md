## Eight player-observed usability findings

1. **First Objectives (O) guidance not visibly prominent.** After closing all three introduction boxes, Objectives (O) does **not** appear highlighted or flashing. User wants that initial recommended control visibly emphasized (highlight or **slow, gentle pulse**) so the novice knows where to start.
2. **Redundant `Next` near Stand Map.** After opening Objectives, Stand Map is visibly highlighted already; the separate word **`Next` beside Stand Map** is unnecessary and should be removed. A gentle highlight/pulse on the actual Stand Map target is sufficient. This is a visual-copy preference, not a request to remove the actual next-action guidance logic.
3. **Poor heading/tab/text hierarchy inside Objectives.** At the top of the Objectives screen there are tabs, then **two lines of text**; the first line has **smaller font than the second**, making it unclear what is more important and creating distraction/disorientation. User requests **larger tabs and tab labels**, **larger normal instructional text**, and an **even larger, more prominent Objectives title** clearly above secondary content. The descriptions `tabs` and `two lines` are user terminology; exact UI elements and layout hierarchy **not yet mapped to source or screenshot**. Do not assert a particular widget or selector is proven defective without inspection.

4. **Objective teaching diagram shifts position after More detail and Esc/reopen.** The initial Objectives opening placed the diagram beside the current objective description, both fitting in one visible screen. The user expanded **More detail**, then collapsed it: the diagram appeared in a different position and required scrolling, unlike the initial state. After pressing **Esc** to leave Objectives and reopening it, the diagram occupied a **third position**. **User requirement:** the same objective diagram remains consistently anchored beside the current description at the initial visible position; expanding/collapsing More detail and closing/reopening Objectives must not unpredictably shift it or require new scrolling to locate it. These are three observations from actual user interaction, not an independently instrumented layout measurement or proven root cause. Reproduction should inspect foldout expansion, scroll-offset persistence/rebuild, scheduled scroll restoration, responsive two-column sizing and panel relayout without claiming any of these is already the cause.

5. **Stand Map opening guidance has redundant copy and unclear keyboard-shortcut formatting.** The user reports an opening pop-up headed approximately **`Stand Map · Find where to look`**. Remove **`Find where to look`** after the Stand Map heading and remove the sentence reported as **`The map tells you to decide where to look, not what to do.`** completely. In Stand Map **More detail**, remove its repeated **`Find where to look`**. In the instruction **`Open it with M when looking for a site to inspect`**, style the **M** with a restrained keyboard-key visual (small keycap outline or subtle tint) rather than undifferentiated prose. Apply the **same unobtrusive keycap convention** to actual keyboard instructions throughout the guidance, including **`Close the map with M, Escape or Back to forest`**: distinguish keyboard `M` / `Esc` from clickable **Back to forest** (not a keyboard key). Keep meaningful game controls and keyboard handling; this is copy and consistent affordance styling, not permission to remove functional controls. User's quoted phrases are spoken descriptions; source match and exact punctuation not yet independently confirmed.

6. **First guided Stand Map visit: Plan Rack needs a gentle pulse in addition to existing highlight.** The user reports that **Plan Rack** is already visibly highlighted when they first navigate to Stand Map but wants it to **flash/pulse subtly on the very first guided visit**, making the next action unmissable. This is about the *relative prominence of adjacent panels*; user has not prescribed an exact colour, animation, or structural redesign. User described an “ideal” alignment but did **not** specify an exact angle, forestry rule, snap threshold, hysteresis/release distance, or whether other nearby racks/edges are snap references. **Do not invent those** or treat a visual suggestion as empirically optimal practice. **User experience intent:** a clearly perceptible novice route **Objectives → Stand Map** with no unnecessary literal `Next` label, and an intuitive typographic scale: Objectives screen title strongest; tab/navigation labels obvious and readable; explanatory text visually subordinate but legible.
