# Manager #200 — D-076 repeated representative rack management and per-year observed effects

**Date:** 2026-11-12. **Verdict:** **PRODUCT DIRECTION ACCEPTED / TECHNICAL SPEC DRAFT / NO SOURCE IMPLEMENTATION RELEASE.** This is a product-level amendment to D-065 Multi-Scale Forestry Management V1 and D-073/D-074/D-075 repeated review/cadence, not an inference that the code can already select a different sample rack. **D-071 remains controlling:** Scenario One uses its five parallel headland-entry access racks; more complicated topology is deferred to future scenarios.

## What the player wants

Manage **one representative rack area** during a substantive CCF management cycle; apply what the player demonstrates to other rack-served areas **only when their current conditions are sufficiently comparable**, after the player reviews/approves the proposed extension and ordinary Work Plan. Repeat that process in later meaningful management years, perhaps sampling a different rack where new conditions justify it. Show how the whole **actually treated** stand evolves in 3D after each year/management cycle. On larger/heterogeneous plantations, different comparable groups may need separate rack-area samples, not one blanket rule.

**Interpretation:** “one” refers here to **a representative rack-area sample per cycle**, not permission to derive a valid stand-wide treatment from one arbitrary tree. The first Scenario One teaching area currently requires **three manually chosen Crop Trees** and has an exact protected footprint; the new workflow must build on, not replace, it. The user has not said every one of the five racks must be personally sampled before scenario completion. This remains an explicit design question only if later user tests reveal a need.

## Draft implementation design

**P0 (keep working):** Existing D-065 first sample + MFM cover/proposals and current annual S1-C reports remain unchanged. Source and qualification work proceeds only from the current accepted UI lineage; [C-01 copy source integration ruling](https://github.com/jermur788/CCF/blob/docs/manager-c01-final-integration-ruling-20261112-v1/Docs/Handoffs/ScenarioOne-Research-Implementation-20261112/MANAGER-C01-393-FOCUSED-GATES-AND-INTEGRATION-VERDICT-20261112.md) staged an isolated candidate but is not a whole-demo acceptance.

**P1 (next safe design):** Extend MFM after first Lesson 5 as a repeated-cycle **sample area selection and new-source proof**, with an unmodified initial centre-rack source. A later-year sample location is one supported rack-served area, not an unconstrained new rack or globally copied tree mark. Player observes and decides on real trees. Current sample/proposal reuse is not assumed valid after annual changes.

**P2 (coverage/commitment):** Run the accepted comparable-area classifier on *current* stand conditions, mark genuinely ineligible units Manual/NotCovered/Excluded, require separate source when needed and never double-assign an area to multiple active prescriptions. Confirm candidates in 3D; stage proposals, accept prescription, then separately approve Work Plan. Keep provenance source rack/area, selected/approved/executed year and explicit ruled-out units.

**P3 (post-year review):** After either `Advance 1 Year` or `Skip to Next Management Year`, update all actual 3D tree/ecology states and show recorded work and current state in **every treated rack area**. A review may compare authentic per-year stand/species aggregates, but not claim a per-rack historical ecological time series absent saved proof. A new per-unit snapshot is a separate persistence/identity gate.

**P4 (future scaling):** Larger and varied properties may require multiple sample groups, each justified by observable differences. Do not change Scenario One's five parallel rack geometry or invent general terrain types. A future scenario-specific design may add true terrain/soil/exposure classification, with separate calibration and review.
