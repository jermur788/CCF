**Process-kill ≠ power loss.** A `SIGKILL` leaves the kernel page cache intact, so the file contents a killed process had *written* survive even if they were never `fsync`ed. Process-interruption checkpoints therefore verify **ordering and state-machine safety of the application's syscalls**, not that data reached stable storage. fsync *presence and order* is checked by trace (W-3); *effectiveness* is HW and unproven.
