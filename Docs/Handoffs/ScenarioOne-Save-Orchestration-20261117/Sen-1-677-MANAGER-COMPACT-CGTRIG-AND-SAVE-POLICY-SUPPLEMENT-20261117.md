## 3. Work order atomicity, replacement, W-A and error handling

- **S03 real pairing:** On successful normal annual resolution, capture the actual created juvenile from the same resolution operation that knows the designated `workOrderId`; do **not** derive pairing from last list element, site coordinate, sorted ID, nearby search, or unrelated history. The `ccfCompactTeaching.plantings` row is written **only** after successful, fully validated settlement and juvenile creation, within a logically atomic commit scope. - **Atomic effect cluster:** validate complete species/site/guard/stock/quote/funds/labour/unique ID/counter/row capacity before mutating, then commit juvenile identity, cash, stock, time, order status `Completed`, actual `resolvedYear`, shelter and outcome, exactly one linked teaching row, and exactly one `WorkResolved` after completed facts. Intermediate save/quit/reload/callback cannot see or persist a half-commit. On error, use staging/rollback that preserves the pre-attempt real state; never fake an earlier success event. Re-entry/reload cannot pay/order/plant/credit twice.
- **W-A Compact-only:** once **Approved**, freeze order type, target tree/site, species, stock, actor (owner vs contractor), shelter/protection, quote and other execution-defining fields **on UI AND all public service/batch routes**. Existing source's group method/shelter setters can demote Approved→Pending; that **must** be guarded before source qualification. For a change, player explicitly cancels approval with confirmation; a decline mutates nothing. Confirmed cancellation removes original order as normal audited `OrderCancelled` **event**, releasing only appropriate reservations. A new distinct Pending order with fresh stock/site/method/shelter/quote must be designated, separately approved and executed. No new `Cancelled` status, no retroactive edit of the old order, no synthetic completion row.
- **Failed/cancelled designated group member:** historical evidence stays intact; no credit for failed/cancelled. Replacement, if player elects it, is a new distinct Pending order and replaces that reserved group slot through actual designated interaction, never growing beyond 4 active group IDs or erasing previous valid successful rows/history. D-084 requires per-tree real actor/shelter choice and normal optional guard/cost, not universal free protection.
- **Save and load:** raw and typed validators enforce the existing closed three-root shape, strict per-profile identity and no fourth root. Persistence failure follows original signed atomic-primary/backup/error design: avoid unsafe `File.Copy` promotion, never mutate the loaded world on refusal; reattempts cannot create extra years or inventory.
