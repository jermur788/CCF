## Precise inspected source diagnosis

In `AnnualReviewView.BuildHeadlines`, four yearly money lines call `TaggedLine`. That helper places source provenance/qualifier and a nested `UiKit.Line` side by side inside a three-column card. `UiKit.Line` uses two horizontal labels unless **the amount string** is more than 12 characters; here `Income less contractor work` is long while its signed amount is relatively short. Thus the *name*, not the amount, is squeezed to **33.75 logical pixels width** at 720p, with repeated single-word fragments. The same UI is unreadable at 1080p. Changing the amount length, text, money value, or the provenance classification would be an invalid fix. The disabled `Show data sources` toggle may hide chips but an always-visible source qualifier is part of the current disclosure contract; do not remove uncertainty just for space.

**Preferred repair:** *locally within Annual Review* build a robust money-entry layout with a source/provenance line and a **full-width name with the numeric signed amount right-aligned either beneath it or on the same row only where real available width permits**. All four headline money rows and any affected detailed annual money rows must remain legible. Avoid changing the general `UiKit.Line` used throughout other screens; if truly necessary, STOP for a scope ruling first. Use distinct local USS classes rather than global layout hacks. Ensure long source names, negative signs and currency units do not wrap into fragments; allow normal vertical growth/scroll instead of clipping. Provenance and `HistoryProvenance.Recorded/Derived` must remain correct; the value “Income less contractor work” is **not full annual net cash** because it excludes material/nursery purchases. No number or year authority changes.
