## B. Proposed operating protocol — *Lean Game-Development Mode*

This is a proposed, owner-approvable addition/clarification to management practice, **not** self-authorized changes to AgentWorkflow, existing approvals or source grants.

1. **Pin the player/research outcome.** Every substantial packet begins with one sentence: “This produces/proves [specific player-visible feature or numerical management question].” Include the smallest true witness and the next blocker. The Manager must reject scope expansion that does not move that outcome closer or prevent a concrete active hazard.
2. **Reuse-first, or justify why not.** Before new source work, inspect working code, fixtures and approved services; produce a concise **REUSE / ADAPT / EXCLUDE** mapping. New replacement code is permitted only with a named gap (API incompatibility, incorrect behavior, unsafe coupling, performance limit or independent model requirement). Keep the existing source owner and protected old-world behaviour.
3. **Triage blockers by what they actually prevent:**
   - **HARD STOP that specific action:** unauthorised/overlapping writes; destructive/unrecoverable change; missing mandatory source approval; active Unity/physical ownership conflict; unsafe save/reference mutation; unsupported qualification claim. Do not bypass it.
   - **CONTINUE IN SAFE LANE:** Editor lease unavailable but independently authorised browser/code/source-only work possible; main integration held but isolated local test candidate allowed; native release tests needed later. Clearly label unrun gates; never treat reduced verification as full acceptance.
   - **SEPARATE BACKLOG / explicit user priority:** tooling refinement, speculative security hardening, broader audit, aesthetic polish and full release suite without a direct current dependency. Pursue only when separately prioritized or a reproduced defect materially prevents the selected milestone.
4. **One obstacle diagnosis then a decision.** On encountering a blocker, perform the minimal bounded diagnosis needed to identify the blocked action and safe alternative. If unresolved, publish one exact blocker receipt and escalate to the responsible owner for disposition; avoid launching a chain of ever-larger audits from a gameplay task. This limits *investigation scope*, not the lifetime of a legitimate worker/Unity lease (D-091).
5. **Use existing risk tiers (not a fourth bureaucracy).** [AgentWorkflow](https://github.com/jermur788/CCF/blob/main/Docs/Project/AgentWorkflow.md) already requires cheapest appropriate checks: Tier 1 for active implementation, Tier 2 for bounded feature qualification, Tier 3 only on milestone/release candidates. For a playable preview use actual Editor compile+movement+nonmutation; for save/ref/RNG/destructive production include relevant independent negative tests and old anchors; for a changed JSON check JSON. Never suppress failed tests or call a source-only pass integrated.
6. **One parent, bounded nonauthor review, one handoff.** Do not book reviewer until a frozen candidate exists. For significant code, simulation, save, destructive or integration work, independent review remains necessary; fix focused findings inside the existing orchestrated task where ownership permits. Low-risk docs punctuation may use mechanical readback without a new agent. A source reviewer must not self-approve.
7. **One-screen progress accounting.** Manager reports: desired outcome; current evidence level; changed paths; mandatory blocker or none; next safe action; user action. Separate IMPLEMENTED, REVIEWED, NATIVE VERIFIED, INTEGRATED and ACCEPTED. Do not make document volume a progress measure.
8. **When scope meaning changes, stop stale design — not all safe work.** Compare latest direct owner intent with the intended outcome; mark old speculative assumptions superseded and revise one bounded task. Do not complete or qualify an obsolete feature simply because review has already been paid for.
