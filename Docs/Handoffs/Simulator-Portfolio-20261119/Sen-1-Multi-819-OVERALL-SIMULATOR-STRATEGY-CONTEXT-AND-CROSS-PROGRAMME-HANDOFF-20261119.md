## 1. What CCF is building and why Scenario One matters

The [Game Brief](https://github.com/jermur788/CCF/blob/main/Docs/Project/game-brief.md) defines CCF as a **3D sustainable forestry and land-management game**, with a physical, spatial decision loop:

> **decide → advance time → walk the landscape → observe and experience consequences → understand why → decide again**

In the current **Stage 1 forestry simulation**, the player assesses individual trees/site conditions, marks and plans actual work, chooses contractor or owner-simulated execution, commits a Work Plan, advances **one ecological year**, and reads/walks the results. Ecological and economic outcomes should be authoritative and shared by execution methods; don't build separate rules simply because an operation might later become a manual physical minigame. The primary audience is small private woodland/farm-forest owners and managers. Forestry ecology should be credible and explicitly label **measured/source evidence, model inference, gameplay calibration and scenario abstraction**. The game should not prescribe one universal best management strategy.

**Scenario One is the reference implementation**, an Irish Sitka spruce plantation transitioning towards continuous-cover forestry, with plausible regeneration, competition, tree planting, browsing/shelters, wood harvesting, deadwood, habitat, costs and genuine management trade-offs. **It is not merely a tutorial or tree-visualization scene**. Its full loop, save/integration contracts and three-species data quality should provide tested components that later independent scenarios can reuse.

Accepted long-term direction from the Game Brief/Decision Log:
- **Stage 1:** build a strong **structured multi-scenario forestry simulator** before wider land uses; **eight independent Irish forestry scenarios** are the accepted programme direction (D-078), each a separate forest, with player *knowledge* carrying over rather than world inventories, cash or geography. Accepted teaching order (D-079): **Inherited Sitka Plantation → Working Mixed Forest → New Farm Woodland → Neglected Broadleaf Wood → Exposed Upland Forest → Atlantic Oakwood → Wet Woodland and River Valley → Complete Irish Forest Estate**. Each later case should add meaningful tree-species/life-stage learning (D-080), subject to individual research and spec approval. This is product intent, **not eight implemented scenarios**.
- **Stage 2:** broaden into fruit/nut trees first, then restoration, biodiversity, water, food production and land-management works (D-054), primarily simulated and menu-resolved before manual tools.
- **Stage 3:** optional solo physical execution of already-implemented authoritative tasks.
- **Stage 4:** potential cooperative persistent world using those same authoritative results. **Do not prematurely build multiplayer infrastructure.**

Strategic invariant: **spatial, physically legible decisions + annual causal ecological outcomes + honest provenance + backward compatibility**. Scenarios and 2D experiments are useful when they strengthen that core, not when they become competing unintegrated simulators.

## 5. How these two programmes should work together — and what must remain separate

**Useful cross-pollination without false integration:**
1. **Source-authoritative annual time:** 2D can expose exact annual timesteps, mortality/competition edge cases and saved histories quickly. Scenario One's full ecology is richer (three species, juvenile browsing/understorey, art and player interaction). Share **evidence methods and verified contracts**, not “identical model” claims or arbitrary constants.
2. **Management workflow concepts:** real per-tree selection, sample→comparable proposals (only when proven), Proposal ≠ Fell mark, explicit Pending Work Plan approval as commitment gate, once-only execution and subsequent ecological results. Same conceptual philosophy, **different implementation proof**. In first-pass Compact and first-pass Multi, there are no internal physical extraction racks. Historical Enlarged80 really does have five and must keep them.
3. **Test and reproducibility:** Multi's deterministic year vectors, golden fixtures, independent mutant reviews, source-to-archive restore checks can improve Scenario One verification discipline; the full Unity E2 loop adds actual player controls, sightlines, 3D visual consequences and saved-world regression. Treat analogies as **test ideas** until source-equivalence evidence exists.
4. **Modular architecture:** prefer domain semantics that survive multiple worlds (Tree identity, Species rules, Work Plan, Annual advances, History, Save admission) separated from world profile/scene/rendering, source-physics model selectors and Unity UI. Use concrete extracted API contracts **after** source inspection, not a costly speculative rewrite “to make both sims share one codebase”. Avoid imposing 2D's 100-Sitka/30m geometry on 3D's 175-tree/36-cell distinct world.
5. **Player outcomes and telemetry:** Multi can be an internal laboratory for scenario calibration and diagnosis, while Scenario One demonstrates why real players should care via physically walked changes. Pair one-year source truth with visual/educational explanations; don't teach forestry facts beyond empirical evidence.

**Do not conflate:**
- Multi **30m 100 Sitka synthetic stand** vs Scenario One **30m 175 actual Sitka + 226 exterior cosmetic scene trees**.
- Multi **one undivided management area** vs old Scenario One **five rack segments**, or use a Multi geometry decision to alter Compact's stand.
- Multi **local Q pass** vs integrated CCF code, saved-profile admission, Unity compile/run or closed-beta readiness.
- New Spec DRAFT vs approved implementation authority; Source Implemented vs Integrated vs Native Verified vs Owner Accepted.
- Scenario One immutable signed **three-profile save** vs Multi deferred future Stage7 persistence.
- 2D candidate marks and proposed comparable regions vs 3D actual Fell marks and approved Work Orders.
