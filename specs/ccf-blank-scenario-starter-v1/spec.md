## 2. Chosen minimal DRAFT direction (subject to review/G4)

Use an **authoring-only, nonpersistent preview mode** in the existing Unity/3D scene/UI composition, not a fictional stand or a new management engine. Duplicate a genuinely new **starter-owned scene** plus the smallest proven scene-local ground/footprint/config/text assets. Reference existing Unity player, UI Toolkit views and shared managers as appropriate; preview mode must not activate manager/ecology gameplay authority, create a default tree spawner roster, preload saved records, unlock work, time-lapse, or fabricate money/history merely to satisfy null dependencies.

**Minimum seam to investigate later:** after source owner grants a bounded file set, allow the existing UI root/affected views to render **read-only disabled/empty presentation** with real ground bounds and without using active management data. This is a proposed capability, **not** a named/new `BlankScenarioManager`/`ScenarioDescriptor` type or class design. It may be accomplished by a verified small guard/projection in the existing components. Whether manager/ecology components are *absent* or *present but inactive* is **not signed here**: first choose the option proving zero state mutation and clean common UI; default preference is **no active management/ecology authority**. If source makes that impractical, return to #425/#844 with an exact minimal alternative, not a dummy forest.

The preview footprint must separate **scene ground dimensions** from saved ecology geometry. Reusing the current square Stand Map unchanged is insufficient for rectangular ground; later implementation must prove a narrow empty-preview map-bounds path or request G4 approval for a small shared map-model/transform change. It MUST NOT alter the historical square ecological grid or old save schema.

## 3. User/editor workflow

1. Developer opens a **new** starter scene directly in Unity Editor under a lawful G1 session. Scene ground is level y=0, default 30 × 30 m; player spawn sits on it, first-person walking/look works.
2. On screen: existing HUD/menu visual foundation and heading labels `Work Plan`, `Stand Map`, `Annual Review`, `Objectives`. Tree-inspection affordance is **unavailable** with zero trees, never a phantom tree.
3. Stand Map shows boundary/size for actual blank site, player if supported, and **zero** tree/path/clearing/rack/juvenile/shelter symbols; no rack editing or rack lessons.
4. Work Plan displays **“No eligible operations in this blank starter.”** Approval, purchasing, harvesting, year advance and quote figures are disabled/absent, not `€0` as if an economy had run. Annual Review displays **“No year has been advanced; no annual review is available.”** No report/history/achievement/financial result is manufactured. Objectives shows **“No objectives configured (development preview).”** without assigning a teaching stage.
5. Save/Load/Continue from disk, F5/F9 and F10/startup actions that would inspect/write historic `forest-save.json` **refuse before file access**; starter is labelled **“Development preview — unsaved”**. A safe in-memory menu close/resume is allowed. No destination save is introduced.
6. Developer duplicates **only starter-owned scene/config/text** and sets a **45 × 60 m test ground**. New preview shows rectangular true bounds without changing old source/prefabs/runtime scripts. The original remains 30 × 30 m. No extra editor/build settings or new global scenario selector.
7. Exit Play; no world persistence or promotion into a player-ready forestry scenario is claimed.
