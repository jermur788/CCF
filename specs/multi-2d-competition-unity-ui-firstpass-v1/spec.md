## Goal and source of truth

When a player selects a tree on the real 2D Sitka stand map, they should understand which other trees compete with it, their distance/DBH/contribution/share, and how a proposed removal would change that tree's modelled competition. They should see the forest in the actual Unity Stand Map visual language, with compact accessible map controls, meaningful felling planning rather than unexplained diagnosis options, and no raw PlanId/execution key in normal UI. They can approve and execute real work under existing strict server contracts. A single source-derived demonstration must work at 1280×720.

**Authorised owner direction** includes all above features; **not yet authorised** is inventing light/seed/regeneration mechanics, modifying G4 shared save/forestry contracts, silently copying mutable Unity scene model, or main/Unity integration. The owner also directs broader future feature parity; this spec is explicitly the **first increment only**, not completion of that goal.

## Required first-pass player experience

**P1 Inspect and competition.** Exact selected live tree shows species/age/DBH/height/crown/status and an intelligible `Competition` section. List strongest 5 nearby living competitors with true ID, distance in metres, DBH in cm, percentage of selected tree's total modelled competition and descriptive low/moderate/strong **share** band, sorted descending contribution/tied ordinal ID. Show remaining count and combined share. Clicking a list row highlights that exact tree on the map; distinguish highlighted competitor, actively selected inspected tree, Pending Fell, Approved standing and executed stump with non-colour indicators. Never direct the player to Fell automatically.

**P2 Planned removal diagnostic.** `Competition now` and `If current pending/approved removals were executed` read-only estimate for the *selected retained living tree*: subtract **only living neighbours actually in the current proposed Fell orders**, sum exact same contributions as current CI; no future seed/light/actual growth projection. If selected target is itself proposed Fell, explain that retention/release estimate doesn't apply and do not present a misleading reduction. Distinguish pending orders and approved-but-not-executed orders. A removal can help a retained tree but is not guaranteed to improve all ecological outcomes. Result must recompute from current one atomic fenced engine view after pending/approve/cancel/Execute/Year+1 or refresh; never cache stale competition under a newer view. No write/feedback from diagnostic to engine.

**P3 Map controls and space.** Compact directional D-pad with + / − / Fit on the *same horizontal strip*, or in a safe unobstructed corner **inside map frame** if true hit targets, grid/north/legend and screen reader interaction are preserved. Reduce helper copy size/verbosity, but preserve 44px minimum interactive hit regions and keyboard labels. At 1280×720 normal zoom no scrolling just to use map navigation/legend and the forest map stays dominant; at 200% literal browser zoom and narrow widths permit stacked page scroll, never clip functional controls.

**P4 Unity appearance.** Use actual Unity `ScenarioOneUi.uss` charcoal/slate panel/body hues and selected-tree ochre, plus `StandMapSymbols` ground/conifer/dead/stump colors with sufficient WCAG AA text and icon contrast; status colors from semantic tokens and glyph/pattern. Improve conifer crown whorl/star form and shading/variation matching **procedural principles** from Unity canopy renderer. Do not claim to directly reuse a Unity `Texture2D`, prefab, or identical pixel rendering in browser. No standalone app font redistribution or new external UI framework. The actual 3D reference may have evolved on other release branches; verify its precise owner-tested candidate/asset revision before final fidelity comparison.

**P5 Felling reason friction.** Owner reports `Poor form/stem quality` and `Damaged/unhealthy` are ungrounded (neither injury nor defect appears in current 2D tree data) and slow work. Do not surface those as factual diagnosis choices; do not auto-diagnose. **For first pass**, retain the existing **required nonempty per-tree reason** (protected C# `AnnualContinuation.AddPendingFell` gate), but streamline to one sensible transparent choice such as `Reduce competition for a retained tree` when a demonstrable retained-tree competitor relation is selected, and `Other (explain)` for independent discretionary/manual cases. The player must actively select/confirm reason; it cannot be auto-written as a fabricated fact or silently defaulted. All reason strings stored exactly and displayed in plan/history; a user can still choose to fell even without a qualifying competition case via honest custom reason. Do not misrepresent an intent as proven desirable or force an unsupported diagnosis. The final precise product language must be reviewed on actual owner screen; protect existing C# reason-required validation and tests, and report if the old five-label spec needs a formal amendment (this spec supersedes those specific unsupported choices after approval).

**P6 Technical clutter.** Integrate user #879 feedback without issuing overlapping writers: ordinary Plan/confirmation/receipt/history show status, selected trees, reasons, year, actual effects and separately confirmed Execute, not long raw PlanId and execution key. Preserve full minted values internally and optional technical Details, exact frozen confirmation and replay/fence checks. Restore from most recent permitted #879 correction if already implemented; **do not overwrite a concurrent source writer**. No fictitious friendly plan ID. Remove only presentation text, never request/state identity.

**P7 Actual core preserved.** At source `03547c6d56b6ba05742e71714d0cc2a4431ecf78` the 2D is one adult Sitka 30×30m synthetic fixture. Preserve 92/92 core and 140/140 smoke baseline, P0 four-way SHA, full source identity, immutable fixtures, no saves, no full Unity scenario parity claim. Approval 0 Fell, separate confirmed Execute, stale replay/anti-double-Fell, host/origin/capability and Year+1 continue unchanged.
