## 1. Player-visible goal and strict milestone boundary
In one playable 2D simulator session, player switches between two **genuinely distinct** labelled synthetic Sitka management areas A/B, inspects each area's actual trees, designates genuine retained Crop Tree(s), voluntarily chooses Fell marks and truthful reasons for selected eligible live competitors/trees in BOTH areas, reviews their separate impacts in **ONE combined Work Plan**, approves the plan with **zero trees felled**, separately confirms Execute **once**, then advances the shared Year +1 and observes real independent results per area. A legitimate no-Fell/manual-only choice remains available.

**MA-1 excludes:** extrapolation from A to B, automated target proposals, Crop ranking transfer, positive ecological comparability, source-backed two-target/control G1, Oak/Beech, site-dependent growth, shared 2D/Unity rewrite, natural recruitment, seed/light, money, save policy, multiplayer and new physical rack topology. These need separate owner/spec authority. UI must state "synthetic authored experiment, not surveyed Irish forest; areas not assessed comparable; edge neighbours excluded by this initial model".

## 2. Area/fixture model and scientific scope
Create a **new versioned, independently identified synthetic experiment**: two non-overlapping area polygons and stable IDs, unique area-scoped tree IDs not colliding with the original `P30-` roster, distinct area seeds, geometry-derived hectares, and own source-bound tree XY/age/DBH/height/status. Areas must differ in actual trees, arrangement, standing density, size and/or competition; never duplicate or spatially slice the protected 30×30 sample fixture for apparent multi-area coverage. Canonical manifest/hash/catalog provenance identifies synthetic authorship; field productivity, soil, exposure, wind and treatment history are UNKNOWN or explicitly synthetic, **not** active new growth factors. Adapt #852's design only after runtime writer inspects the actual compilation model; its proposed schema values are not automatic mandates.

**Approved initial ecological simplification:** each area's competition, growth and mortality are evaluated *within that area only*, using unchanged source `AnnualRules.Calculate` and appropriate per-area areaHa, trees and deterministic seed. Area boundary is a management boundary and this model intentionally omits across-area crown/competition effects; UI discloses the limitation. Each area produces its own living/dead/felled count, basal area, competition and age/growth results and history, while experiment shares one ecological year.

## 3. Single true in-process transaction
One authoritative immutable experiment root, **one lock and one publication** of all area states and plan/event/receipt revisions. Do not compose two independently committing `AnnualContinuation` instances. A combined plan carries exact source/experiment/area IDs, tree IDs, year and revisions, explicit manually stated reasons, per-area Crop/Fell mutual exclusions, pending/approved state, one engine-minted execution key and recorded event. Approval changes **no tree**. Execute revalidates the *entire* batch before publication, commits all indicated areas once or refuses all without mutation, and returns one global receipt plus per-area real before/after counts and basal area; same-key identical replay returns same receipt, altered replay/stale data refuse.

**Owner-selected safeguards:** a proposed Fell batch that would leave **any currently populated managed area with zero living trees** is refused whole, even if other areas survive. An area that became naturally empty through mortality may remain an empty current-state row while other populated areas advance. Refuse Year+1 if every area is naturally empty (no fictitious continuation). Pending or approved work across any areas requires explicit user consent to cancel **the whole experiment's unexecuted work** at zero Fell before Year+1. No crash durability promised: all-or-none is within one in-process authority only.

## 4. Minimum player workflow and humane controls
- Switch actual A/B live maps/inspection panels without losing correct area selection. Distinguish AreaId/TreeId and current area membership. Crop marks persist as current-session authoritative state, not merely JS highlight; Fell eligibility and reasons match qualified #882 source.
- Add one manual eligible Fell in each area, keep existing crop protection and free no-action choice; ordinary UI hides execution capability and huge raw IDs, retains readable exact tree IDs/reasons and keyboard navigation.
- One Work Plan lists both area sections and per-area plus total proposed Fell; `Approve` alone changes neither roster; separate clear `Execute` confirmation; single receipt and Year+1 report. A plan touching only one area, or zero Fell, is legitimate.
- Player can see consequences separately, including cases of zero growth, natural death or no work; label unknown site, unmodelled ecology and no scientific transfer.
