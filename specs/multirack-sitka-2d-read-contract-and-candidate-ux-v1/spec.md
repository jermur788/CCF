1. A lawful custodian admits original fixture bytes under the existing source trust process, or lawfully identifies **one genuine #725 completed report** tied to the same admitted fixture, or later one **actual #789 single committed** annual state. The read adapter **never** takes an arbitrary browser object or rounded table as a biological source. The legacy #784 F3 private key is **not** an exportable contract.

3. Validate *all* identity, provenance, row, bit, stage and aggregate constraints before publication. Stage diagnostics absent in source remain unavailable; distinguish a deliberately skipped evaluation from computed zero. No source mutation or callback to annual engine during conversion.
4. Atomically expose **one immutable full read frame** with an adapter-owned opaque local read revision; compare previous adapter revision before delivering new frame. ### 3.4 Bit codec, numeric kind and spatial transform

**PROPOSED codec** for any source f32 scalar is a tagged exact 8-lowercase-hex bit word {k:"f32", b:"hhhhhhhh"}; for f64 it is 16 lower-hex digits {k:"f64", b:"hhhhhhhhhhhhhhhh"}. These are candidate internal read words, not #725 CLI or #784 frozen method names. Reject wrong length/case/kind, nonfinite NaN/Infinity, fabricated f64 widening of a raw f32 value, mismatched source bit words and unsupported units. Preserve source signed-zero if legitimately present; integer year/IDs/count/XY-mm/RNG 24-bit numerator remain exact integers. Tree DBH/height/crown/CI/centred X/Z and area are **f32**; stand BA/Dq/RD, mortality reductions and sums are **f64**. Nha must retain its **source f32 division/evaluation** and any independently established subsequent widening; no blanket all-f64 conversion, no text-decimal roundtrip or arbitrary tolerance. Display round-off is cosmetic and **never** feeds eligibility, density, comparison admission or biology.

**Derived P1 source coordinate rule (accepted geometry):**

- Raw fixture origin = southwest corner. xMm increases east, yMm increases local north; both are integer millimetres in [0,30000) for this fixture; this is synthetic local orientation, **not Irish OS grid / latitude / measured north**.
- Transform ID **p1-square30-corner-to-centred-xz-v1**. Compute signed 64-bit dxMm = xMm − 15000, dzMm = yMm − 15000. Divide each by binary64 **1000.0**, then cast each **exactly once** to IEEE754 f32: X_m = f32(f64(dxMm)/1000.0), Z_m = f32(f64(dzMm)/1000.0). If both raw mm and pre-existing centred fields are supplied, compare **bitwise** xBits/zBits; mismatch ⇒ entire frame refused. Never apply this offset to original P0 polygon/Unity40/80 without its own approved transform.
- For a north-up 30m Canvas view, source-plane local East = X + 15m; local North = Z + 15m. Screen vertical increases downward: at neutral camera display y decreases with local North, then apply A-owned Fit, pan, zoom; invert mapping for hit-testing. CSS pixels, device-pixel-ratio backing pixels and biological metres remain three distinct units. A source crown radius 3m at 20 **CSS px/m** is **60 CSS px radius**, not 60 diameter or a DBH estimate.
- A owns one nearest **stem-centre** hit test, not crown coverage, with stable ordinal-ID ties; no secondary C map hit-test and no f32 coordinate recalc via screen pixels. Unknown coordinate transform/version/domain, nonfinite or geometry out of range ⇒ read refusal, not guessed repositioning.
