The owner's 16 Nov direction is **full playable core first, finished art in parallel, assets one by one, reuse existing tracked five-rack visual assets rather than remake**. This new spec extracts **only what art must be created or reused**; the graphics spec remains a separate DRAFT until a scoped alignment revision, not silently superseded. #617 owns parent/planting wording separately.

## Binding creation and interface rules
1. **Keep core unblocked:** core programmers may use only suitably sourced existing tracked art and **new neutral built-in Unity primitive placeholders** (under an approved core implementation spec/lane) with correct geometry and source state; they do not need final art approval for the primitive's appearance. Any copy/derivative of existing protected materials requires source/licence/ownership approval.
2. **Asset input contracts:** each asset author takes signed *visual dimensions and appearance states* from the core/graphics interface once available. Collision, movement envelope, player reach, G1 positions and exact path routing remain **core technical authority**. The asset package supplies render bounds/pivot/scale and collision-envelope suggestions for the scene owner to verify, not autonomous physics.
3. **Asset output contract:** one coherent immutable version per item with original editable source, exports (when authorised), texture channel semantics (normal OpenGL/Y+ vs importer), topology/LOD/poly budget, UV/texel/colour map, source provenance and licence/reuse rights, hashes, local scratch location and presentation screenshots. No new third-party pack without separate permission.
4. **D-032 is OPEN:** asset production/Unity import/commits/releases remain blocked outside already-granted #611 **one-off temporary local-only disposable** material experiment. Before production export/commit, approve binary tracking/source/archive/licence rights and exact owning worktree. Windows optional **asset-authoring scratch only**; Scenario One production source/Unity integration and candidate qualification on **Linux**. The specific owner-authorised #611 Windows scratch native URP look is not production host precedent.
5. **One-by-one integration:** art author hands off A-xx; independent artefact/provenance review; Linux Unity graphics integrator in own approved lane applies to separate Compact-only assets/materials; targeted Tier-1/2 proof and versioned accepted reference; no full Tier-3 per art item. Existing visuals may remain during later asset production if game state legible/accurate.
6. **Historical isolation:** never mutate `ForestTest.unity`, 80m racks/planks, `Forest Ground.mat`, `Forest Path.mat`, Legacy40, E80 Rack V2/MFM, frozen Reference Future v1 or actual v1–v24 saves. No Windows Player build without owner personal exact candidate test and separate authorisation.
