# Scenario One — Repeated Representative Rack Management V1

**STATUS: DRAFT / READY FOR MANAGER DECISION — NOT APPROVED FOR CROSS-SYSTEM IMPLEMENTATION.** 12 November 2026. D-076 product direction is accepted. This is a proposed *later-cycle extension* to APPROVED D-065 MFM V1 and D-064/D-071 five-parallel-rack Scenario One, not a change to the shipped first demonstration. [Read-only helper](../scenario-one-management-followon-browser-readonly-v1/spec.md) has separate narrow approval only.

## Desired player experience

In a substantive treatment cycle, the player demonstrates judgement on **several real trees in a representative rack-served area**, reviews whether a similar treatment would suit other **currently comparable** rack areas, confirms candidates individually in 3D, approves the proposed prescription and then separately approves the Work Plan. After real annual ecology steps, they see **every actually treated place** change, inspect the current stand and historical work, and make another considered choice in a later cycle. A different source area is appropriate when conditions are materially different; five racks do **not** mean five compulsory hand-marked racks.

**Player flow proposal:** inspect fixed third-rack lesson (preserve credit) → mark three Crop Trees and execute local release → inspect/accept comparable covered units → confirm actual proposed trees → approve prescription (creates Pending work) → review/approve Work Plan → advance one year or skip through distinct authoritative annual steps → walk all treated areas → review actual resolved work and annual stand observations → choose whether a new current-state sample, fresh treatment or manual work is warranted.

A new cycle may contain one source if sufficient, additional independently demonstrated source(s) for a genuinely different comparable group if approved, or a Manual/NotCovered remainder. A single arbitrary selected tree is never a stand-wide sample or compulsory success condition.

## Proposed requirements

**R1 — First teaching unchanged.** Third-rack Crop Tree judgement and local release still earn initial teaching credit. New later sample must NEVER migrate its history or alter first-sample frame, old rack plans, teaching threshold, mark colours or world identity.

**R2 — Later player-chosen demonstrated source.** For a new substantial management episode, the player chooses a supported rack-served area from a currently confirmed rack layout, walks it, judges multiple living trees and executes a real sample treatment in a bounded footprint. The number/spacing of selected future crop trees and treatment size require authentic calibration; no universal copy of the first lesson's three-tree and 30% rule. Demonstration must be *more than a single tree*, but do not invent a numerical forestry standard. A previously used area can be chosen again only following an explicit fresh demonstration and live recalculation, not silent reuse of an old prescription.

**R3 — Evidence-based scope of comparability.** Derive current rack-served area geometry, exclusions, masking, species and current density/mean DBH/competition from valid sources. Only covered comparable areas are eligible; others stay NotCovered/Excluded/Manual. Test homogeneous and intentionally heterogeneous Sitka patterns before deciding tolerances. Do not treat unmodelled slope/soil/moisture/wind as measured similarity. Oak/Beech quantitative automated proposals remain excluded pending distinct approved species algorithms.

**R4 — One source owns each area for the episode.** Proposed state identity: episode ID, source rack ID, source area ID, source sample Year, rule/calibration signature, intended coverage-unit IDs, explicit excluded/manual units and current validation stamp. For any two sources proposing the same area in an episode, **fail closed to Manual/Conflict until the player explicitly chooses an owner and the system revalidates**. Never union their candidate Fell marks or create duplicate orders. One source per unit is an episode ownership rule, not a claim a unit cannot be treated again in a later cycle. Old executed orders stay historical, and a source from an earlier year is never auto-applied again. This is a *proposed new persistence contract*, not presently saved.

**R5 — Commitment remains staged.** A sample outcome informs a proposed rule. Proposals are not red Fell marks; confirm exterior Crop Trees/candidates individually in the forest. Prescription acceptance/approval generates Pending ordinary work only after fresh checks; Work Plan chooses labour and authorises work separately. No automatic work after a skipped year, no unapproved quality/wind/seed-tree judgement, no override of manual player marks. If any link or source invalidates, the affected proposed work stays Manual/ineligible until re-evaluated; past successfully completed tasks are never rolled back.

**R6 — Timely recalibration.** A new annual tick changes forest state; a current-state rule/coverage becomes stale when source evidence or proposed work no longer agrees. Reinspect and rederive before future approval; do not assume a retained historical source still calibrates later growth. Never silently change the treatment status of earlier executed units.

**R7 — Observed effects with three distinct precision tiers.** 
- **Tier 0 (existing authority):** all actual felling, growth, regeneration, canopy and habitat change through current live authoritative tree/ecology state and must be visible in 3D in all actually treated areas, not just the sample.
- **Tier 1 (possible read-only):** actual historical resolution year + prescription + coverage-unit work grouped from verified saved orders/events, distinct from current proposals, access clearances and unlinked old orders. New readout helper may support this once compiled; do not parse area IDs as definitive source racks.
- **Tier 2 (NOT PRESENT):** per-rack past yearly ecological metrics such as local canopy light or seedling change. Requires new calibrated measurement, saved history/migration/hashes, current-vs-historic geometry policy and explicit product approval; never label stand-total deltas per rack.

**R8 — Separate time cadence and learning.** D-077 one-year/skip runs normal years and stops at decisions; the suggested 4-year review is navigation, not a forced harvest timetable. D-074 spaced stand-management learning must not be implemented from this MFM draft or satisfied by merely choosing another rack. The D-073 review owns truthful selected-year/latest stand comparisons, not new MFM permissions.

## Manager product choices needed before release

1. **Delivery slice:** Recommend first ship Tier 0 current 3D plus Tier 1 honest executed-work history. Confirm whether optional Tier 2 per-rack annual ecology is essential for demo; if yes, add a separate fully approved persistence/data contract and old-save coverage.
2. **Cycle/source:** Select one source per new episode when sufficiently homogeneous, and allow additional sources only for **different, freshly validated comparable groups**. Does a reused source require an entirely new local completed sample, as proposed? Record the exact eligibility and provenance.
3. **Overlap:** Accept fail-closed Manual/Conflict by default, with explicit one-source-per-unit selection, or a different deterministic conflict policy backed by tests. Do not silently prioritise rack number or nearest centre.
4. **Multi-source release sequencing:** Should V1 include **two sources in one episode** or should first release permit one current source plus manual heterogeneous remainder, with tested two-source extension later? Recommend one+manual first if full multi-source save proof is costly; preserve the user goal through a subsequent extension.
5. **Episode/new-source save fields:** Prove explicit versioning, archived world hash handling, source area identity and old-save lack-of-source display before a code release. The current sourceRackId/sourceYear are not evidence that alternate later source areas are already supported.
6. **Substantive sample size:** Set a defensible *gameplay-calibrated* number/coverage/decision test after running real stands, not copy one arbitrary tree, not unconditional equal spacing and not a new Irish standard.
